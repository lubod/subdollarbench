## Why

The operator asked what the CLI needs (2026-10-27). The reviewer read
`src/config.rs`, `src/main.rs` and `scripts/sql-cell.sh`. Most commands
still serve the retired per-task benchmark. That cleanup is graded work
and waits for the retired-code round. Five things matter before the
calibration cell, and none of them touches a graded path:

- **`campaign run` doesn't default to the official cell**
  (`src/config.rs:39-61`):

  | | default | official (R23 D4, `sql-cell.sh:11`, `:22-24`, `:97`) |
  |---|---|---|
  | budget | $1.00 | $0.99 |
  | wall | none | 480 min |
  | `--timeout-min` | 60 | 120 |

  A cell started without the wrapper is not the official cell, and
  nothing says so.
- **`sql-cell.sh` doesn't check what it publishes.**
  - It builds the working tree as it is, uncommitted edits included
    (`:51`).
  - It doesn't check the flake bar, though AGENTS.md ("Rules version")
    requires a 20-pass bar on the graded content before the next
    published cell.
- **The binary can't name its rules.** `Cli` has no `version`
  (`src/config.rs:16-22`), but published results must name their rules
  version (AGENTS.md). `fingerprint()` (`src/report/rules.rs:835`)
  already computes the stamp cells record.
- **`eval` and `replay` check four SQL stages.** `run_sql_stages_sync`
  runs stages 0-3 (`src/main.rs:113-140`, `total = 4`). `eval --task
  sql` and `replay` of an sdb-sql workspace call it (`:824`, `:1548`),
  so they print a pass rate out of 4 for a 21-ticket ladder.
- **Help text names retired tasks:**
  - `run --task` and `enqueue --task` default to `redis` (`:96`,
    `:731`).
  - The help for `leaderboard`, `runs` and `lboard` gives `'http',
    'redis', 'pdf'` as examples (`:198`, `:343`, `:975`).
  - The doc comment "Export a static read-only portal" is on
    `regen-reviews` (`:234`), and `portal` has none (`:276`).
  - `log` takes a `run` argument it ignores (`:869-872`).

## Items

### F1. `campaign run` defaults are the official cell

- Defaults: `--budget-usd 0.99`, `--wall-min 480`, `--timeout-min 120`.
  Effort stays `high` and harness `omp`, as in `sql-cell.sh:28-29`.
- One place for the numbers: name them once (for example constants
  next to `CampaignAction`). Use them in clap and in a check that prints
  `[campaign] not the official cell: <what differs>` when a run uses a
  larger budget or wall, or turns the wall off.
- `sql-cell.sh` keeps passing the values explicitly; its defaults stay
  equal (`:22-24`).

Acceptance:
- [ ] Parsing `campaign run --name sdb-sql --model m` gives 0.99, 480
  and 120 — test: `r40_f1_campaign_run_defaults_are_official`.
- [ ] The note appears for `--budget-usd 1.5` and for `--wall-min 600`,
  and not for the defaults or smaller values — test:
  `r40_f1_unofficial_cell_note`.

### F2. `sql-cell.sh` refuses a dirty tree and a missing bar (D2)

- **Before the build:**
  - Refuse when a tracked file differs from `HEAD`. Untracked files are
    fine, except under `src/`, `campaigns/`, `extensions/` or
    `build.rs`.
  - Refuse unless `<git-common-dir>/sdb-gates/flake-<key>.txt` exists
    for the current graded content and its last summary says
    `RESULT: PASS`.
- **The key comes from `flake-bar.sh`,** not a second copy:
  - add `scripts/flake-bar.sh --key`, which prints the key and exits;
  - `sql-cell.sh` calls it.
- **`SDB_CELL_SMOKE=1`** as in D2.
- **The `[cell]` line** adds the flake key and the record's result.

Acceptance:
- [ ] `scripts/sql-cell.sh --self-test`, in a temporary repo, covers:
  - a dirty tracked file: refused;
  - no record: refused;
  - an `IN PROGRESS` record: refused;
  - a `FAIL` record: refused;
  - `PASS`: allowed;
  - `SDB_CELL_SMOKE=1` with no record: allowed, with the SMOKE line;
  - `SDB_CELL_SMOKE=1` with budget 0.99: refused.

  Check: the self-test's output, quoted in the notes.
- [ ] `flake-bar.sh --key` prints the same key as a real run's record
  header, and `flake-bar.sh --self-test` still passes — check: the
