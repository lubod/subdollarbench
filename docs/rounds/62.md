## Why

- **R61-6.** `mapped_ready_proofs` (`scripts/proof-map.sh:77-122`)
  attributes a hunk in `src/pipeline/tests.rs` by the `fn` name in git's
  Rust hunk header, and matches only `^fn `.
  - The stage proofs are `async fn` (`#[tokio::test]`). A change inside
    one gets the header `async fn
    test_pipeline_eval_only_sql_stage12_concurrency_live() {`
    (reproduced at `round61`), so it counts as unattributed and selects
    all 19 proofs.
  - Git's header is the last function line *before* the hunk. So a hunk
    on a function's doc comment or signature is attributed to the
    function before it. A newly added proof is never selected.
- **R61-7.** When the selection is all 19 proofs, `--ready` is slower
  than full: the fast set runs first, then every proof serially. Round
  61: `--ready` took 59 min 28 s, full took 52 min 8 s
  (`61.md`, Implementer notes, F6).
- None of these paths is graded (`scripts/graded-paths.txt`), so this
  round doesn't move the bar's key, and the bar on `539a58e0c8c8` keeps
  running through it.

## Items

### F1. Attribute `async fn` hunks, and changes at a function's head

- `mapped_ready_proofs` accepts `fn`, `async fn`, `pub fn` and `pub
  async fn` in the header.
- A hunk is attributed to the function whose span contains the hunk's
  new lines, not only the header's function. Compute the spans from the
  HEAD file: each top-level `fn` from its doc comment and attributes to
  its closing `}`.
- A hunk that touches two functions selects both. A hunk outside every
  proof (a helper, a `use`, a constant) still selects the full set.

Acceptance:

  - a change to a proof's doc comment selects that proof, not the one
    before it;
  - a hunk spanning two proofs selects both;
  - a helper change still selects the full set.
- [x] Seen failing: with the `^fn ` match restored, the `async fn`
  fixture fails.

### F4. The bar stops on a harness failure (R61-10)

- In `run_chunk` (`scripts/flake-bar.sh`), a run whose log has no
  `test result:` line, or whose exit code is 127, is a harness failure,
  not a proof FAIL. The bar records `HARNESS <t> <reason>`, stops, and
  exits non-zero. `summary` treats a `HARNESS` line as
  `RESULT: FAIL (harness: <reason>)`.
- A filter that matches no test (`running 0 tests`) counts as a harness
  failure too, since that is R61-1's failure mode.

Acceptance:

  - a fake `run_one` that prints `nice: cargo: No such file or
    directory` and exits 127;
  - one that prints `running 0 tests` and exits 0.

### F1/F2. Hunk spans and new proofs

- `fn_spans` (`scripts/proof-map.sh`) reads the HEAD
  `src/pipeline/tests.rs` with Python: it finds each top-level `fn`
  (`fn`, `async fn`, `pub fn`, `pub async fn`), starts the span at the
  doc comment/attributes directly above it, and ends it at the matching
  closing brace (strings, raw strings, char literals, line and block
  comments are skipped while counting braces).
- `mapped_ready_proofs` turns each `@@ ... +c,d @@` into the new-line
  range (a deletion uses the insertion point `c`). A hunk selects every
  span it intersects. A span that is not a bar proof, or a hunk that
  intersects no span, selects the full ready set (the old "shared
  helper" rule). A proof the fast set already ran is skipped.
- `bar_proofs_at` (`scripts/bar-proofs.sh`) gives the bar list at the
  merge base; every HEAD proof not in that list and in
  `scripts/live-proofs.sh` is selected as `new proof`.
  `select_ready_proofs` gives `new proof` priority over a hunk reason,
  and core priority over both.
- Self-test (`scripts/proof-map.sh --self-test`) passes:
  - `an async proof-body hunk selects its proof`
  - `a doc-comment hunk selects its proof`
  - `one hunk selects both proofs it spans`
  - `a helper hunk selects the full set`
  - `a docs-only change selects nothing`
  - `a new proof is selected as new proof`
- Seen failing for F1: with the span parser's `head` regex restricted to
  `^fn` (the old header match), the self-test exits 1 at
  `[self-test] an async proof-body hunk did not select just that proof`
  and the fallback prints all 19 `unattributed hunk: full set` lines.
  Restored: PASS.
