## Why

without an answer:

- opencode's request got no response headers for 5 minutes, failed with
  `provider.transport` "Timed out waiting for response headers", and was
  sent again, four times: w3 turns at 02:32:20, 02:37:20, 02:42:22,
  02:47:26, 02:52:34 UTC
  (`runs/campaign_sdb-sql_openrouter_anthropic_claude-haiku-5.5_20261116_021028_w3/live.log`);
  w1 the same, 02:30:14 to 02:50:29.
- The live health check counted 5 empty turns (over 5 %), wrote
  `live provider fault: 5 empty responses in 74 turns` (91 for w3), and
  held the grid (`scripts/grid.sh:568-574`).
- Each abandoned request was still charged: w3's session billed
  `7 call(s), $0.16212150` for 3 answered turns, where a haiku call there
  costs about $0.001.

**Cause:** the round-85 billing path reads OpenRouter's whole response
before it sends a byte back (`resp.read()`,
`extensions/egress_proxy.py:110`), then answers with a
`Content-Length` body (`extensions/egress_proxy.py:128-131`). A streamed
answer that takes longer than opencode's 5-minute header wait can never
arrive, and the identical retry takes as long again. The bar and the
rehearsal use a stub; the R85-3 probe made two short calls; `.47` had no
proxy. None could show it.

## Items

### F1. The billing path streams the response through

The `/api/v1` billing path forwards the upstream's status line and
headers as soon as they arrive, then each body chunk as it arrives
(chunked or SSE), never buffering the whole response. It keeps a copy
(or the tail that holds the final `usage` chunk) and appends the same
`billing_record` (`extensions/egress_proxy.py:31`) when the upstream
ends. A non-streamed JSON answer still works. A client that hangs up
mid-stream still produces a billing record for what the upstream sent.
The upstream read time-out stays a per-read guard (180 s), not a whole-
response limit.

Acceptance:
- [ ] A stub upstream that sends headers at once and then SSE chunks
      over a period longer than the client's header wait: the client
      receives the headers and the first chunk before the upstream
      finishes, and `billed.jsonl` gets one record with the final
      chunk's `id` and `usage.cost` — test:
      `r87_f1_billing_proxy_streams`
- [ ] A plain JSON (non-stream) answer is forwarded whole and billed as
      before — test: `r87_f1_billing_proxy_plain_json`
- [ ] A client that disconnects mid-stream: the proxy doesn't crash,
      serves the next request, and bills the first — test:
      `r87_f1_client_hangup_still_billed`
- [ ] `r85_f1_billed_from_the_calls` and `r85_f1_cell_isolation` still
      pass
- [ ] Each new test seen failing against the buffering proxy

### F2. A turn interval never wraps backwards to a day

`src/campaign/health.rs:154`, `:263` and `:274` take a turn's duration
as `(end + 86_400 - start) % 86_400`, so an end stamp a few seconds
before its start (a resume's lines) reads as 86,394 s, the
`turn_secs_max` both stopped runs show. Wrap only for a real midnight
crossing (the end is more than 12 hours "before" the start); any other
backwards step is 0 s.

Acceptance:
- [ ] 23:59:50 → 00:00:10 is 20 s; 02:51:51 → 02:51:45 is 0 s; the
      grid's `p50 > 180` warning isn't raised by such a step — test:
      `r87_f2_no_backwards_day`
- [ ] Seen failing
