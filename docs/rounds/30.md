## Why

Findings from rounds 29 and 31 (`29.md`, `31.md`, Review):

- **R29-1: the first GitHub CI run failed at clippy.**
  - Run `40100387906` (`29.md`, "R29-1"): `dtolnay/rust-toolchain@stable`
    installed Rust 1.99. The bench and the gate use 1.92.0.
  - The newer clippy raises 6 lints, all in `src/verifier/sql/`
    (`pgwire.rs`, `toy.rs`, `txn.rs`).
  - No test ran on the runner, so the next run may show more.
- **R29-2: CI runs the fast test set twice.**
  - `.github/workflows/ci.yml` runs `bash scripts/gate.sh --fast`. That
    runs `fmt`, `clippy` and `cargo test` with the `SQL_PERF_LIVE` skips
    (`scripts/gate.sh:86-97`).
  - CI then runs `cargo llvm-cov` over the same set, and runs
    `cargo check`, `fmt` and `clippy` again outside the gate.
  - So a run takes twice as long and is twice as exposed to flakes.
    Instrumentation also slows timing-sensitive tests: the implementer
    saw `stage6_transactions_live` slow down, and the pubsub mock p99
    flake (`29.md`, Implementer notes).
  - The skip list is written twice: as the same `awk` over
    `src/pipeline.rs`, in `gate.sh:91-95` and in `ci.yml`.
  - It holds 15 names: the 14 proofs that take the `SQL_PERF_LIVE`
    lock, plus `test_tests_gate_sensitivity_end_to_end`.
  - The other 11 live ladder proofs take no lock: `stages_0_3`, stages
    4-10, and the 5, 8 and 11 lite ones (for example
    `test_pipeline_eval_only_sql_stage6_transactions_live`). So the fast
    gate and CI run them, in parallel with the rest. They are part of the
    measured 84.63 %.
- **R29-4: the Board's rules fallback reads a field that does not
  exist.**
  - `loadRulesVersion` (`src/web/index.html:2986-2993`) falls back to
    `(await fetch('/api/status')).json().rules_version`.
  - `StatusResponse` (`src/web/server.rs:149`) has `sqlite_version` and
    `cap_price_basis`, but no `rules_version`.
  - The page injection (`serve_index`, `server.rs:734`) covers the Board
    today, so the fallback is dead code.
- **R31-1: six needle checks in `src/pipeline.rs` still fail without the
  log.**
  - They print only `"missing {needle:?}"`, with no log.
  - Two are SQL proofs: `test_pipeline_eval_only_sql_stages_0_3_live` and
    `test_pipeline_eval_only_sql_stage4_persistence_live`.
  - The other four are the proxy, queue and http full-ladder proofs and
    `test_pipeline_eval_only_sql_stage6_after_lite_stage5`.

**Why these go together, now.**

- The 20-pass flake bar failed on `5ebad6e` (`27.md`), so its record is
  void. It starts again from zero once this round merges.
- Any graded change after that resets it again, at about 16.5 h per bar.
- So R31-1 (in `src/pipeline.rs`, a graded path) lands here too, and one
  bar covers rounds 30 and 31.
