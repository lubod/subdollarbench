## Why

Round 83's F4 probe (notes): opencode makes one extra "summary" call at
the end of an `opencode run`, and the runner's `step_finish` events
don't carry it. A luna run with `--title` (the runner passes it,
`src/sandbox/opencode.rs`) made 3 calls costing $0.00066553 at
OpenRouter; the events priced 2 of them at $0.00061231, missing
$0.00005321 (8 % of that tiny run, about 0.005-0.02 % of a $1 phase).
The session db's `session_v2` row priced all 3 at $0.00066553, equal to
OpenRouter's charge. The runner prices each `step_finish` with the
snapshot (`step_usage`, `src/sandbox/opencode.rs`), so the phase's
scored cost and its budget check miss that call. Operator, 2026-11-14:
fix it before any `.47` career.

## Items

### F1. The run's cost includes every call

At the end of each `opencode run` (every attempt and resume), before the
per-run data dir is removed (`RunDirs`), read the session's token totals
from the run's own opencode db (`session_v2`, the session id the runner
passed; every session in that db if opencode made more than one) and
reconcile them with the summed `step_finish` tokens:

- tokens the db has and the events don't are priced with the same
  snapshot rates (`compute_cost_with_cache_and_write`) and added to the
  run's stats (`cost_usd`, the token counts, a call count if the stats
  carry one), with one log line `[COST] reconciled: +<tokens> tokens,
  +$<usd> (calls the events didn't report)`;
- the db never lowers the count (if the events show more, keep the
  events and log it);
- a missing or unreadable db is logged and leaves the events' count,
  never a harness fault.

The budget stays enforced on the events during the run (the summary
call comes after the last step); the reconciled cost is what the phase
records and scores.

Acceptance:
- [x] On a canned db holding one more call's tokens than the canned
      events, the run's cost equals the snapshot price of all calls, and
      the `[COST] reconciled` line names the difference — test:
      `r84_f1_cost_counts_the_summary_call`
- [x] Equal totals add nothing; a missing db leaves the events' count
      and logs it; the db never lowers it — same test or a sibling
- [x] Each assertion is seen failing (`scripts/seen-failing.sh`)

### F1 (done)

`OpenCodeRunner::reconcile_db_usage` (`src/sandbox/opencode.rs:133-213`)
opens the run's `<data>/opencode.db` read-only, sums every `session_v2`
row (`tokens_input`; `tokens_output` + `tokens_reasoning`;
`tokens_cache_read`; `tokens_cache_write`), and adds only the positive
per-bucket differences to the stats, priced with
`compute_cost_with_cache_and_write`. The log line is
`[COST] reconciled: +<tokens> tokens, +$<usd> (calls the events didn't
report)`; `+<tokens>` is the step-event `total` shape (fresh +
completion + cache write), and the cached reads are priced too. A lower
db bucket is logged and kept at the events' value; a missing or
unreadable db logs `[COST] reconcile skipped: ...` and leaves the stats
(never a harness fault). The call site
(`src/sandbox/opencode.rs:1296-1313`) is after `child.wait()` and the
reader/stderr joins, before the billing/outcome snapshot, so it runs
for every attempt and resume. The budget stays on the events (the
round's rule); only the scored `stats` is reconciled.
