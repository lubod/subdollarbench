## Why

The 2-lane smoke (`docs/DECISIONS.md` #22, step 3; operator "smoke",
2026-10-31) started lane 0 (worker 0) and then refused lane 1 (worker 1)
before any spend:

```
Error: campaign campaign_sdb-sql_openrouter_deepseek_deepseek-v4.1-flash-1017_20261031_072428 (pid 1550075) is already running — if that process is gone, delete /home/ubuntu/subdollarbench/runs/.campaign.lock
```

- One lock file covers the whole runs directory:
  `campaign_lock_path()` is `runs/.campaign.lock`
  (`src/campaign.rs:1543`), "one campaign at a time" (`:1538`), taken
  by every `campaign run` (`src/main_campaign.rs:523`).
- `scripts/grid.sh` starts every lane in the same `runs/` (`:33`,
  `:356`), so `--lanes 2` or more fails at the second lane's first
  phase. The grid self-test uses stub cells that never take the lock,
  so nothing ran two real cells at once before.
- Two more things two cells share, found while writing this round:
  - **The campaign id** is `campaign_<name>_<model>_<%Y%m%d_%H%M%S>`
    (`src/main_campaign.rs:514-516`): two lanes that start the same
    model in the same second share one directory.
  - **The engine's Docker sweep** (`src/web/server.rs:620-632`, every
    60 s while the engine is idle) reaps a running `subdollar-*`
    container older than 3 h (`MAX_RUNNING_ORPHAN_AGE_SECS`,
    `src/sandbox/docker.rs:1928`) unless its run is in `live_run_ids`
    (`src/web/server.rs:658`), which knows only the engine's own runs,
    not a CLI campaign's. This is older than lanes, but a longer grid
    makes it likelier.

## Items

### F1. One campaign lock per worker

- The lock path takes the worker: `runs/.campaign.lock.w<N>`.
  `campaign run` takes its own worker's lock; a second cell on the same
  worker is still refused, with the same message.
- `live_lock_holders()` returns every live holder. Its users:
  - `effective_state` (`src/campaign.rs:1666`): a cell is `running`
    while *its own* lock is live, whichever worker holds it;
  - `/api/status` (`src/web/server.rs:214`): a `campaigns` list of every
    holder; `campaign` stays, as the first holder, for old clients;
  - the console launch (`src/web/server.rs:1807`): refused only when the
    worker it would use is held;
  - the queue (`src/web/queue.rs:1017`): unchanged in effect, SQL jobs
    wait while any campaign lock is live.
- A legacy `runs/.campaign.lock` (written by a binary before this round)
  is still read as a live holder until its process exits.

Acceptance:
- [ ] Two locks on workers 0 and 1 are both taken; a second taker on
  worker 0 is refused and names the holder; a dead holder's lock is
  replaced — test: `r53_f1_lock_per_worker` (temp paths, no real lock),
  seen failing on master.
- [ ] Two real binary processes hold the locks of two workers at the
  same time, in a temp `SDB_RUNS_DIR`, and `live_lock_holders()` sees
  both — test: `r53_f1_two_processes_two_locks`. If no CLI path holds
  the lock long enough without spending, add a hidden test hook, or ask
  under Spec questions.
- [ ] `effective_state`, `/api/status` and the console launch read every
  holder, and a legacy lock file still counts — test:
  `r53_f1_lock_readers_see_every_worker`.

### F2. Two cells never share a campaign directory

- Two cells that start the same model in the same second on different
  workers get distinct ids, and the directory is created exclusively
  (`create_dir`, not `create_dir_all`), so two writers never share one.
- The id format stays readable by `scripts/grid.sh`
  (`result_get campaign_id`), the board, the chain lookup
  (`--chain`) and `sql-cell.sh`'s result file.

Acceptance:
- [ ] Two ids made in the same second for the same model on workers 0
  and 1 differ, and a second exclusive create of one directory fails —
  test: `r53_f2_same_second_ids_differ`, seen failing on master.

### F3. The engine's sweep keeps a live campaign's containers

- The idle sweep (`src/web/server.rs:620-632`) and the startup sweep
  (`:675-687`) treat every container and network of a live campaign
  (any `live_lock_holders()` entry) as live: the age gate never reaps
  them, and `prune_labeled_networks` keeps their networks.
- The implementer names, in the notes, how a container is tied to its
  campaign (the `sdb.run` label value, `src/sandbox/docker.rs:1854`) and
  checks that every container a CLI cell starts carries it.

Acceptance:
- [ ] A running `subdollar-*` container older than
  `MAX_RUNNING_ORPHAN_AGE_SECS` whose run belongs to a live campaign
  lock is kept; the same container with no live lock is reaped — test:
  `r53_f3_sweep_keeps_campaign_containers` (the age and the docker
  calls injected; no real container), seen failing on master.
