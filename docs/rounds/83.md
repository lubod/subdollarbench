## Items

### F1. The negative probe uses a provider that can't serve the model

The probe's wrong pin is fixed to `novita` (or `baidu` when the pin is
`novita`) (`scripts/model-check.sh`, `opencode_check`, `wrong_pin`).
Novita serves deepseek and glm-5.3-flash, so the "wrong" pin was served
and both failed. Pick the wrong pin from OpenRouter's endpoints API
(`/api/v1/models/<id>/endpoints`): a provider slug that serves other
models but **not** this one; say in the record which slug and why. If
the endpoints call fails, the check fails with that reason (never a
silent fallback to a fixed slug).

Acceptance:
- [ ] With a canned endpoints answer that lists `novita` for the model,
      the probe never picks `novita`; with one that doesn't, it may —
      check: `scripts/model-check.sh --self-test`
- [ ] A failed endpoints call fails the check with its own reason — same
      self-test

### F2. The "beside a job" refusal is accurate

- **Its own unit:** the check doesn't refuse because of the systemd unit
  it runs in (`$INVOCATION_ID`, or the unit name passed by
  `scripts/detach.sh`); it still refuses beside any other `sdb-*` unit.
- **Dead reservations:** a `res-<pid>-*` file whose PID is not alive
  doesn't count as a running grid; the refusal lists only live ones.
  `scripts/grid.sh` removes its own reservations on exit (normal, error
  and signal) if it doesn't already, and says so.

Acceptance:
- [ ] Inside a fake unit named as its own, the check runs; beside another
      fake unit, it refuses — check: `scripts/model-check.sh --self-test`
- [ ] A `res-` file with a dead PID is ignored; one with a live PID
      refuses — same self-test
- [ ] A grid killed with SIGTERM leaves no `res-` files — check:
      `scripts/grid.sh --self-test`

### F3. Peak-priced models are checked off-peak

minimax (and deepseek) are priced and run off-peak only (R75-1,
`docs/DECISIONS.md` #30). The check either refuses them outside their
off-peak window, with the window in the message, or applies the peak
rate to the expected bill and says so; the record names which. Read the
window from the provider's published pricing (say where) or from a
single table in the repo that the grid's off-peak rule already uses;
don't add a second copy.

Acceptance:
- [ ] A peak-time check of minimax is refused (or priced at peak) with
      the window named; off-peak it runs as now — check:
      `scripts/model-check.sh --self-test` with a fake clock

### F4. Why hy4 and luna bill about 1.6x the snapshot through opencode

Both passed the omp check on `.46` and the `meta/muse-ember` check
matched to the eighth decimal (round 79), so the snapshot rows aren't
simply wrong. Candidates the implementer should test, cheapest first:

1. **Calls the expected bill doesn't count.** The usage delta includes
   every call on the key during the check (the title call, now on the
   career model since round 82; the negative probe if it was billed;
   opencode's own retries). The expected bill comes from the positive
   session's `session_v2` row only. Count the requests (the stub's
   method, or a local logging proxy in front of OpenRouter that records
   each response's generation id) and price each.
2. **Cache writes.** luna's session wrote 4,343 cache tokens; the
   snapshot prices `cache_write` at $0.125/M. Check what OpenRouter
   charged per call (its generation API, `/api/v1/generation?id=`, with
   the ids from (1)) against the snapshot's four rates.
3. **hy4's cache reads.** 9,536 cached tokens priced at $0.021/M in the
   snapshot; if Tencent billed them at the prompt rate, the expected
   cost is far off.

Write what each call cost and why, per model, in the notes. Then:

- if the check's expected bill was missing calls, fix the check;
- if a snapshot row is wrong, say which field and the evidence under
  **Spec questions** and stop: the snapshot is the scored cost and the
  cap (`src/cost/model_prices.json`), and changing it needs the
  operator's word;
- if opencode makes extra calls in a **cell** too, say how many and
  what they cost per phase; that is a scoring question, also under
  **Spec questions**.

Acceptance:
- [ ] The notes give, for hy4 and luna, every call of one check with its
      generation id, tokens by kind, OpenRouter's cost and the snapshot's
      price for it, and the sum against the usage delta — check: notes
- [ ] The outcome is a fix with a test (seen failing) or a spec question
      with the evidence — check: notes
