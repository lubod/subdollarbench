## Items

### F1. One re-measure, then the same ±0.1

Today the test asserts once, on one `run_workspace_at`
(`src/pipeline.rs:4966-4993`). Change it to:

- **One check.** A helper decides whether a `PerfScore` is within
  tolerance: every workload `|ratio - 1| <= 0.1`, and the score is
  `Some` and within `|score - 1| <= 0.1`. That's the same rule as
  today, in one place. On failure it returns a message that names each
  workload out of tolerance with its ratio, `correct`, `note` and
  `numbers`, as the current assert does.
- **One re-measure.** When the first run is out of tolerance, the test
  prints that message to stderr, then measures once more on a fresh
  `covtest_dir` (fresh containers, a fresh reference workspace). It
  fails only when the second run is also out of tolerance. The failure
  message carries both runs' messages.
- **Host load is evidence.** Each run's message includes
  `/proc/loadavg`, read just before and just after that run. If the file
  can't be read, the message says so and the test doesn't fail on it.
- **No more than one re-measure.** A systematic bias, like a reference
  that isn't 1.0 against itself, still fails: it fails twice.
- **The retry logic is unit-tested without Docker.** Factor it as a
  small function that takes a closure returning a `PerfScore` (or the
  error) and returns `Ok`, or `Err(message)`. The live test calls it with
  the `run_workspace_at` closure.
- The test's doc comment says what changed and why (R59-1, a loaded
  host), and that the tolerance itself is unchanged.
- The test keeps its name, so `scripts/live-proofs.sh` and the bar still
  find it, and it still takes `SQL_PERF_LIVE` first.
