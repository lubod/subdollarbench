# Round 72: the expanded careers use the board's width

Status: open
Opened: 2026-11-09, base `round-72-open` (operator: "open 72"; asked for in the draft's Why)
Branch: `round72`
Rules: `2026-10-19.45` (unchanged: display only)

## Why

On the deployed board (round 71, `portal/index.html` of 2026-11-09),
opening a model's "×3 careers ▸":

- **At 1440 px:**
  - the `<details>` lives inside the model cell (`td.col-model`, about
    570 px), so the 12-column career table scrolls inside half the row,
    while the Points, Perf, Spend and Tickets-agreed columns to its
    right stay empty for the whole height;
  - the Career column is about 60 px wide. Each career label repeats the
    full model name ("deepseek/ deepseek- v4.1- flash-1017 · career 1 ·
    2026-11-04", one fragment per line), then an "effort high" badge,
    then 21 ticket squares 3 per line, so **one career row is about
    300 px tall** and the other cells hold one short line each.
- **At 390 px:** the same, narrower still. The label takes 7 lines and
  the squares 7 rows, and the table shows only its first 1.5 columns.

## Items

### F1. The expanded careers span the full table

- The careers of a model render in a **full-width row** under the model
  row: `<tr class="more-row"><td colspan="N">` where N is the board's
  column count. The "×3 careers ▸" toggle stays where the reader expects
  it, under the model's name.
  - The toggle must still work with no JavaScript (round 69: `<details>`
    is the only interactivity, and a small inline script may only add
    convenience). One way: the full-width row holds the `<details>`, and
    its `<summary>` is styled to sit under the model name. Another: a
    `<details>` per model row with CSS that lets its content span the
    row. Your choice; say which in the notes.
- The agreement strip (round 71 F1, one per model) and the dot strips
  move with it, and the "agree …" link (R71-2) still lands on the strip,
  opened.

Acceptance:
- [ ] Test `r72_f1_more_row_full_width`: each model's career table is
  inside an element that spans every board column (a `colspan` equal to
  the header's column count, or the equivalent), not inside
  `td.col-model`.
- [ ] `r71_f1_one_agreement_strip` and the R71-2 anchor test still pass
  unchanged in substance.

### F2. A compact career label

- Inside a model's expansion, the Career cell drops what the model row
  already says:
  - the label is **"career 1 · 2026-11-04"** on one line (`white-space:
    nowrap`). It still links to the same results anchor, and the full
    model name sits in its `title`;
  - no "effort high" badge per career (the model row has it). A career
    whose effort differs from its model row keeps a badge.
- The 21 ticket squares sit on **one line** in their own column
  ("Tickets"), or under the label spanning the row's width; never 3 per
  line.
- Target: at 1440 px an expanded career row is **at most 72 px tall**.

Acceptance:
- [ ] Test `r72_f2_compact_career_label`: an expanded career's label
  cell has no `/`-split model name and no effort badge when the effort
  matches; the label carries `title` with the full model id.
- [ ] Measured in a headless browser at 1440 px, the tallest expanded
  career row on the real export is at most 72 px. The method and number
  go in the notes (for example: `chrome-headless-shell
  --remote-debugging-port`, then `getBoundingClientRect()` on each
  `tr.career-row` with every `<details>` open).

### F3. The phone view of the expanded careers

- At 390 px the expanded careers are **cards, one per career**, with no
  sideways scroll box:
  - line 1: the label ("career 1 · 2026-11-04") and the points;
  - line 2: perf, spend, highest ticket, kept green;
  - then the 21 squares, wrapped evenly (for example 11 + 10);
  - duration, turns and tokens in one muted line.
- The dot strips keep label and value on one line ("duration 4.9 h",
  not "duration / 4.9 / h").

Acceptance:
- [ ] Test `r72_f3_phone_cards`: under the phone media query the
  expanded career table renders as blocks (the rows and cells `display:
  block` or `grid`), and no element inside the expansion has a fixed
  `min-width` above 390 px.
- [ ] 390 px screenshots, collapsed and expanded, in the notes.
