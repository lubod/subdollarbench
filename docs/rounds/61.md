## Why

- **The 20-pass bar keeps restarting before it finishes.** The last bar
  that passed is `flake-9c90cfcf4b7b.txt` (2026-10-27, rules `.42`).
  Four bars have started since (`14a590f26873`, `4b04de447b27`,
  `4b11760f6ea4`, and the next one on round 60's key), and none has
  finished. So no official cell has run on v2 (`.43`-`.45`). The newest
  run directories are the 2026-10-31 smoke cells.
- **A test-only change moves the key.** Both hashes take whole files:
  - the flake key: `git ls-tree` over `scripts/graded-paths.txt`
    (`scripts/flake-bar.sh:16-21`);
  - the rules fingerprint: `digest_files` over
    `src/report/graded-files.txt` (`src/report/graded_hash.rs:93-109`,
    `build.rs:19-31`).

  About 25,000 lines of `#[cfg(test)]` code sit inside 36 graded files
  (for example `src/campaign.rs` from `:3886`, `src/pipeline.rs` from
  `:3986`). Round 59 changed only a test in
  `src/verifier/sql/concurrency.rs` and still restarted the bar, and so
  will any future fix to a unit test. Test code isn't in the release
  binary, so it can't change a grade.
- **One failure anywhere fails the whole bar.** The bar is 28 proofs ×
  20 runs = 560 runs, with zero failures allowed
  (`scripts/flake-bar.sh:88-122`). For it to pass with even odds, each
  run's flake rate has to be below about 1 in 800. Each flake found has
  cost a round and then a bar from zero, about 17 h each (`58.md`,
  `59.md`). Round 60 handles the problem for one proof; F4 handles it in
  the bar.
- **Long jobs die with the session that launched them.** On 2026-11-02
  the bar died at about 12:39Z when the opencode service restarted, and
  it left four containers behind (`59.md`, "After the merge"). Nothing in
  `scripts/` detaches: there is no `systemd-run`, `setsid` or `nohup`.
- Source: the reviewer's process review (2026-11-02, recommendations 1,
  2 and 4); the operator asked for this draft ("draft 61").

## Decisions for the operator (before open)

**Decided** (operator, 2026-11-02, "a a yes"): **D1 = a**, **D2 = a**,
**D3 = yes**. Details below.

- **D1, the bar's standard (F4).**
  - **(a), recommended:** a failed proof reruns once right away. A
    failure that passes on its rerun is "cured", and is allowed at most
    once per proof and twice per bar, with the cured proofs named in the
    result.
  - **(b):** keep zero tolerance and drop F4.
- **D2, how long jobs detach (F5).**
  - **(a), recommended:** run `loginctl enable-linger ubuntu` once (a
    host change, so the operator does it) and launch with `systemd-run
    --user`. The job then survives a service restart and a logout, and
    `journalctl --user -u` keeps its log.
  - **(b):** use `setsid nohup` with a pid file. It survives a service
    restart, but there's no unit and no journal. Linger is `no` today.
- **D3, sequencing.** The bar on round 60's key would be thrown away
  when F1 lands about a day later.
  - **Recommended:** hold the bar until round 61 merges, so one bar
    covers both rounds. Round 60's own live check is its full gate.

### F1. Unit tests move into `tests.rs` files (no test changes)

  becomes `#[cfg(test)] mod tests;`, and its body moves unchanged to the
  module's `tests.rs`. For example `src/pipeline.rs` goes to
  `src/pipeline/tests.rs`, `src/verifier/sql/concurrency.rs` to
  `src/verifier/sql/concurrency/tests.rs`, and `src/bench/mod.rs` to
  `src/bench/tests.rs`.
  - The module keeps the name `tests`, so every test path stays the
    same: `pipeline::tests::r45_f1_reference_scores_one` and so on.
  - The notes list the files that moved (36 at the time of drafting).
- Other `#[cfg(test)]` items, such as helper functions or test-only
  fields in production code (`src/sandbox/docker.rs` has 4,
  `src/sandbox/omp.rs` 3), stay where they are, and the notes list them.
  This round moves only `mod tests`.
- One commit: text is moved only, no test body changes, `cargo fmt` is
  allowed.

### F4. A failed proof reruns once (D1 = a)

- In `run_chunk` (`scripts/flake-bar.sh:130-156`), a FAIL keeps its
  line and its log as today, and then the same proof runs once more
  right away. That run is recorded as `TEST <t> RERUN PASS|FAIL <s>
  <utc>` (with `log=` on a FAIL). A rerun doesn't count toward the 20.
- `summary` (`:88-122`):
  - `RESULT: FAIL (...)` when a rerun failed, when a proof has more than
    one cured failure, or when the bar has more than two;
  - otherwise `RESULT: PASS` at 20 runs each, with `(cured: <t>, ...)`
    appended when there were any;
  - each proof's line shows `cured=N`.
- `sql-cell.sh` (`:71`) and `grid.sh` (`:222`) accept `RESULT: PASS`
  with or without the suffix, and still refuse FAIL and IN PROGRESS.
- AGENTS.md ("Flake bar") states the standard. The reviewer edits it at
  the merge, in the same commit, per the file-ownership rules.

Acceptance:
- [ ] Self-test fixtures, one per outcome:
  - a cured failure gives `RESULT: PASS (cured: beta)`;
  - a failed rerun gives `RESULT: FAIL (beta)`;
  - two cured failures on one proof give FAIL;
  - three cured failures across the bar give FAIL;
  - with the fake `run_one`, a FAIL is followed by a `RERUN` line for
    the same proof.
- [ ] `sql-cell.sh` accepts a record ending `RESULT: PASS (cured: x)`
  and refuses `RESULT: FAIL`: its existing preflight self-test, or a new
  one. Seen failing: with the rerun removed from `run_chunk`, the
  cured-failure fixture fails.

### F5. Long jobs outlive the agent session (D2 = a)

- `scripts/detach.sh <name> -- <command...>` launches the command so
  that a restart of the opencode or Claude service can't kill it. It uses
  `systemd-run --user --unit sdb-<name> --same-dir --collect` (D2 = a).
  It refuses, and says why, when linger is off for the user
  (`loginctl show-user "$USER" -p Linger`), because the job would then
  die at logout.
- It prints how to follow the job (`journalctl --user -u sdb-<name>
  -f`, or the log path) and how to stop it by PID or unit, never with
  `pkill -f`.
- It refuses when a job with the same name is already running.
- AGENTS.md (reviewer, at the merge): bars, grids, load bars and probes
  start through `scripts/detach.sh`.

Acceptance:
- [ ] `scripts/detach.sh --self-test`:
  - a job launched from a subshell that then exits (and whose process
    group is killed) still writes its marker file;
  - a second launch with the same name is refused;
  - the job's exit status is readable afterwards;
  - with linger off (a stubbed `loginctl`), it refuses and names the
    fix.
