### F2. A graded crash is `failed`, not `fault`, and keeps its lite

**What happened.** On P2 ticket 10 and P3 ticket 11, the same chain of
events:

1. Haiku's turn hit the 65,536-token output limit (`[TOKENS] … output:
   65536`).
2. That truncated an `edit` tool call ("Tool call arguments are not valid
   JSON. Parse Error: Unterminated string").
3. The next request got `400 Provider returned error`, and OMP exited
   with status 1.

**Why it loses the lite.**

- `src/pipeline.rs` ~:5200 sets `agent_failed`, and `src/campaign.rs`
  ~:2893 / ~:2988 turn `agent_failed || infra_error` into status
  `fault`.
- The `else if fault` branch (~:2935) records `Failed` and skips the
  lite.
- Yet the verifier did grade the round (11: 10/11 stages, the late perf
  check failed), and `harness_fault` was `None`.
- Ticket 11 has a lite (`11_indexes_lite`) and never got it. 14 and 16
  were then skipped, and P4 spent its catch-up on 11-lite.

**Change.**

- A graded round with `harness_fault == None` and a crashed or non-zero
  agent exit gets status `failed`, and the lite runs as for any failed
  full.
- `fault` is kept only for a real `harness_fault` (agent never started,
  provider billing/auth, infra error).
- Apply this in the full path, the lite path (`status2`), the catch-up,
  and the manifest backfill at ~:1652.
- Record the crash, e.g. `failure.kind = "agent_crash"`, with the
  truncation noted, so the Board can say why.

**Harness side.**

- Find out why a truncated tool call becomes a fatal `400` instead of a
  tool error the model can recover from.
- The raw requests are in `~/.omp/logs/http-400-requests/` (P2
  `1792604062634-1ip1xyd644zg6.json`, P3 `1792609214369-39ux4ljnknnfh.json`).
  They may hold credentials: read fields, never paste them.
- If OMP can hand the parse error back and continue, do it, and log
  `[OMP] truncated tool call`. If not, say why in the notes.
