## Why

The same four-part audit as round 89 (2026-11-17), the money and grid
half. Re-checked by the reviewer:

- `scripts/sql-cell.sh` never writes `billed_usd` into its result
  (`grep -c billed scripts/sql-cell.sh` is 0), so the grid's bill
  checks never see the real bill.
- The `.48` haiku ledger has two `provider_fault` rows at $0, while
  their `status.json` shows `live.campaign_spent` $0.186 and $0.196.
- A faulted phase-2 run carries `chain_from`, so the grid's rerun of it
  is refused as "chain already used" (`src/main_campaign.rs:559-565`).

## Items

### M1. A killed or faulted phase's spend reaches the ledger and the cap

When a cell is killed (live fault, stop, crash, reboot), `sql-cell.sh`
writes no result and the ledger row gets `${cost:-0}`
(`scripts/grid.sh:686-687`, `:723`). Read the run's spend from its
`status.json` (`live.campaign_spent`) and its `billed.jsonl` when no
result exists; the cap counts it.

Acceptance:
- [ ] A killed cell's ledger row carries its spend, and the cap
      reservation counts it — test (grid self-test with the real
      campaign binary's status file shape): `r90_m1_killed_phase_spend_counts`
- [ ] Seen failing

### M2. The real bill reaches the grid, and peak hours are checked per phase

- `sql-cell.sh` forwards `billed_usd` (`scripts/sql-cell.sh:446-487`).
- The cap counts `max(list, billed)` per phase.
- Before each phase reservation the grid checks the model's peak window
  (deepseek, minimax; the windows `model-check.sh` already knows) and
  waits for off-peak instead of starting a phase at peak.
- The live check holds the grid when a running phase's
  `billed_ratio` passes 1.25 (`scripts/grid.sh:536-593` reads
  health.json already).

Acceptance:
- [ ] `billed_usd` is in the cell result and the ledger; the cap uses
      the larger of list and billed — test: `r90_m2_cap_counts_the_real_bill`
- [ ] A phase due at peak waits for off-peak — test:
      `r90_m2_no_phase_starts_at_peak`
- [ ] Each seen failing

### M3. A rerun after a fault works for every phase; a recovered canary reopens the lanes

- The provider-fault rerun keeps the chain (`scripts/grid.sh:747`), and
  the faulted successor makes `chain_already_used` refuse it
  (`src/main_campaign.rs:559-565`). A run hidden as a provider fault
  (`.portal_hidden`) or stopped live (`.live_stop`) must not use up its
  chain; the grid's rerun of phase 2, 3 or 4 runs.
- `.canary_failed` (`scripts/grid.sh:564`, `:572`) is cleared after a
  clean rerun, so the other lanes open (`:576`); a grid that does not
  open them says so in the log.
- The post-phase provider-fault check counts `[BENCH-POLICY] turn=`
  lines (`scripts/grid.sh:513-527`), which opencode never writes; apply
  the live thresholds to the final `health.json` instead.

Acceptance:
- [ ] A provider-fault rerun of phase 3 starts and chains from phase 2
      — test (real campaign binary, stub agent): `r90_m3_fault_rerun_any_phase`
- [ ] A recovered canary opens the other lanes — test:
      `r90_m3_recovered_canary_opens_lanes`
- [ ] A phase whose final health is over the fault thresholds is
      recorded `provider_fault` under opencode — test:
      `r90_m3_post_phase_fault_reads_health`
- [ ] Each seen failing

### M4. The call in flight when a session ends is counted

On READY, the turn cap, the wall or the budget, the agent container is
removed while opencode may already be in its next call
(`src/sandbox/opencode.rs:1395-1408`); the bill is read
(`src/sandbox/opencode.rs:1481`) and the sidecar removed
(`src/sandbox/opencode.rs:920-927`) before the sidecar writes that
call's record. Before reading the bill, wait (bounded, e.g. 90 s) until
the sidecar has no request open, then read; a record still missing is
named in the log. Also: the model prose fix is round 89 F3; a transient
`docker inspect` failure must not read as "the sidecar died"
(`src/sandbox/opencode.rs:914-915`): retry, and require
`State.Running == false`.

Acceptance:
- [ ] A session ended while a slow stub call is open still bills that
      call — test: `r90_m4_in_flight_call_is_billed`
- [ ] One failed `docker inspect` doesn't end the run — test:
      `r90_m4_inspect_blip_is_not_a_death`
- [ ] Each seen failing

### M5. The records can't be faked by stale state, and the key covers the grade

- A rehearsal counts only rows written by this run: a reused rehearsal
  ledger whose careers are already complete must not write a PASS record
  (`scripts/grid.sh:314-363`, `:630-639`; `runs/.grid-rehearsal-ledger.tsv`
  holds old ok rows).
- The graded key includes what decides a grade or what a phase
  inherits: `Cargo.toml`, `Cargo.lock`, `src/grading.rs`, `src/main.rs`,
  `src/lib.rs`, and `src/main_campaign.rs` (the phase-to-phase copy and
  the perf tie-break) — `scripts/graded-paths.txt`, with the class
  (grader or plumbing) of each.
- A paid grid refuses to start without `--cap` (`scripts/grid.sh:36`).

Acceptance:
- [ ] A rehearsal on a ledger that already has complete careers runs
      them or refuses; it never writes a PASS for content that didn't
      run — test: `r90_m5_stale_rehearsal_ledger_never_passes`
- [ ] Each listed file changes the graded key — test:
      `r90_m5_graded_key_covers_the_grade`
- [ ] A paid grid without `--cap` refuses — test: `r90_m5_paid_grid_needs_a_cap`
- [ ] Each seen failing
