- Rounds 65 and 67 changed only harness plumbing, pricing, recording and
  display. Their bars re-ran proofs whose behaviour those changes can't

- **Next up:** new models (glm-5.3, gemini-3.8-flash, ...) each need a

  row is another 7 h bar.

    questions**.
- A new **grader key** (`flake-bar.sh --grader-key`) hashes the grader

### F3. The model check before a grid (DECISIONS #28)

- `scripts/model-check.sh <model>`: one tiny call (a "reply ok" prompt)
  through the **sandbox's** omp, the same image and `~/.omp` mount the
  cells use, with the model's pin from `src/cost/model_prices.json`.
  Then OpenRouter's generation API. It passes when:
  - omp sent exactly the model id (no fuzzy match);
  - OpenRouter served that model (its dated id starts with the model id)
    from the pinned provider;
  - the bill is within 1.25× of the snapshot price for that call.
- It writes `sdb-gates/model-check-<model-slug>.txt` (the sent and
  served ids, the provider, the ratio, the UTC time, the sandbox image
  digest). It never prints the API key.
- `grid.sh` refuses a paid grid for a model without a PASS record made
  within 7 days on the current sandbox image digest.

Acceptance:
- [ ] `scripts/model-check.sh --self-test` (no network: canned omp and
  generation responses): a fuzzy match (sent `tencent/hy4-preview` for
  `tencent/hy4`), a wrong provider and a 2× bill each fail; an exact
  match passes.
- [ ] `scripts/grid.sh --self-test`: no record, an old record and
  another image's record each refuse; a fresh matching record allows.
- [ ] One live run in the notes, for `openrouter/z-ai/glm-5.3`
  (unpinned is fine if no row exists yet; then the provider check is
  skipped and the record says so). It costs well under a cent.

### F4. CI is green again

CI has failed on every push since 2026-11-02 (the last success:
`0c3e707`, lines 84.70 %). Three causes, from the run logs:

1. **Coverage under the gate (every run).** Lines fell to 82.48 % at
   `2798819` (round 61, which moved test modules into `tests.rs` files)
   and read 83.23 % at `0507473`, under `--fail-under-lines 84`
   (`.github/workflows/ci.yml`). The tests themselves pass. Likely
   mechanism: the 19 live proofs that CI skips now live in their own
   `tests.rs` files, and their never-run bodies count as missed lines.
   - Fix: measure the product code, not the test code: add
     `--ignore-filename-regex '(^|/)tests\.rs$'` (or the equivalent
     for every test-only file) to the `cargo llvm-cov` line, and update
     its comment. Measure locally first (`cargo llvm-cov` 0.8.7 is
     installed; take the shared test lock) and record the new line
     percentage. The gate stays at 84, or rises to the new measured value
     rounded down (round 29's rule); it never falls.
   - If the product-code coverage is under 84 even so, stop and ask
     under **Spec questions**: don't lower the gate.
2. **`sandbox::omp::tests::test_run_agent_invalid_model_docker`
   (intermittent).** CI builds the sandbox with `OMP_VERSION=18.4.2`
   (`Dockerfile.sandbox:37`), where omp prints "Model ... not found" and
   then waits until the test's 5 s watchdog, which ends the run as `Ok`;
   the test asserts `res.is_err()`. Make the outcome deterministic: a
   run that ends because the agent never started (the model-not-found
   text, or no agent turn before the watchdog) is an error. Don't widen
   the assertion to accept `Ok`.
3. **The sandbox build's `bun` download (one run: HTTP 504).** Retry the
   download (for example `curl --retry 5 --retry-all-errors`) so a single
   network error doesn't fail CI.
