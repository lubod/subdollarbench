## Why

`GRADED_FILES` (`src/report/rules.rs` ~:734) lists only the retired
tasks. For sdb-sql, the only active campaign, the stamp moves only when
`RULES_VERSION` is bumped by hand.

None of these are covered:

- `campaigns/sdb-sql/campaign.json` and the stage prompts;
- `src/verifier/sql/*`;
- the scoring in `src/campaign.rs` (tier points, lite weight, catch-up
  0.4x, `CATCH_UP_SLOTS` ~:2522) and, since round 23, the money rules:
  `CELL_BUDGET_USD`, `TURN_GUARD` (~:1947), the cap reserve and floor
  (~:357), and the pool weights `stage_weight` / `runnable_weight_sum`
  (~:393);
- the late checks in `src/pipeline.rs`;
- the candidate-facing text: the directives in `src/sandbox/omp.rs`
  and `src/sandbox/opencode.rs`, and the dollar line `session_budget_line`
  (`src/pipeline.rs` ~:1316).

This was the old roadmap item "campaign spec + stage prompts + suites join
GRADED_FILES", which was never done. It matters at the freeze: without
it, a silent change to a prompt or a grader goes unnoticed.

**R1:**

- `graded_files()` sweeps `campaigns/sdb-sql/stages` and
  `src/verifier/sql` recursively and sorts the result.
- Moving the scoring and money constants to `src/scoring.rs` keeps the
  behaviour: every removed literal 0.4 / 1 in `campaign.rs` is now
  `CATCH_UP_WEIGHT` / `DEFAULT_LITE_WEIGHT` / `DEFAULT_TIER`.
- The prompt templates in `src/prompts/` are filled with `.replace`.
- Keeping the retired tasks in the list, with the reason given, is

**Findings:**

- **R24-1 (blocker): the operator's test model isn't in the snapshot.**
  - `src/cost/model_prices.json` has no
    `deepseek/deepseek-v4.1-flash-1017` entry. The catalog price is
    $0.15 / $0.60 / cache read $0.003 per M.
  - Since R2, the paid-launch check reads only the snapshot, so on `.39`
    every test cell is refused. That model is the test model (operator,
    2026-10-22; `TODO_CAMPAIGNS.md`).
  - Fix:
    - add the entry;
    - add a test that every model named in `TODO_CAMPAIGNS.md` /
      `scripts/` as a test or calibration model resolves to a snapshot
      price.
- **R24-2 (blocker): a snapshot entry matches as a substring, so model
  variants get the wrong price.**
  - `snapshot_rates` (`src/cost/calculator.rs` ~:275) uses
    `m.contains(match)`. Examples from the catalog today:

    | Model | Priced as | Its real price |
    |---|---|---|
    | `deepseek/deepseek-chat-v3.1` | $0.2574 / $1.0287 | $0.25 / $0.95 |
    | `mistralai/mistral-small-3.2-24b-instruct` | $0.15 / $0.60 | $0.094 / $0.25 |
    | any `:batch` variant | full price | about half |
    | any `:free` variant | paid price | free |

  - The entry order decides which entry wins: `gemini-2.5-flash-lite`
    must stay above `gemini-2.5-flash`.
  - Fix:
    - Match the exact catalog id, after stripping `openrouter/` and
      lower-casing. No match means refused.
    - Rename the field `match` to `id`.
    - Test: `deepseek/deepseek-chat-v3.1` has no price unless it has its
      own entry.
- **R24-3 (blocker): cache-write tokens are priced at $0.**
  - The new in-session price uses only `input`, `cacheRead` and `output`
    (`src/sandbox/omp.rs` ~:1215). OpenCode uses only `input`,
    `cache.read`, `output` and `reasoning` (`src/sandbox/opencode.rs`
    :43-58). The final cost uses the same three totals.
  - OMP's usage has a separate `cacheWrite` field
    (`@oh-my-pi/pi-ai` `usage.ts`). On Anthropic models it holds most of
    each turn's new context.
  - The Haiku `.36` log shows `input: 2, output: 559, cached: 12854`:
    about 1,100 new tokens per turn that are neither `input` nor
    `cached`.
  - Under `.38` they were billed through `usage.cost.total`. Under `.39`
    they cost nothing, so Haiku's bill and the cap's spend drop by the
    write share. That's a silent scoring change between models that
    cache (Anthropic, Gemini) and models that don't.
  - Fix:
    - Add `cache_write_per_million` to the snapshot: the catalog
      `input_cache_write`, or the prompt rate when the catalog has none.
    - Count `cacheWrite` (OMP) and `cache.write` (OpenCode) in the
      in-session stop and in the final cost.
    - Test: a usage event with only `cacheWrite` tokens costs more than
      $0.
- **R24-4 (next → freeze round 27): the stamp itself isn't stable.**
  - `fingerprint_files` / `fingerprint_root` use `DefaultHasher`, whose
    algorithm Rust doesn't promise to keep between releases, and keep only
    32 bits.
  - The files are read from `SDB_HOME` on disk, but the prompts and the
    snapshot are compiled in with `include_str!`. A binary built from an
    older tree can therefore report the new tree's stamp.
  - At freeze: use SHA-256, and hash the compiled-in content
    (`include_str!`) for the files that are compiled in.
- **R24-5 (note): the template order matters.**
  - The `.replace` chain fills in `{{PROMPT}}` first. A ticket prompt
    that contains `{{PORT}}` or `{{TEST}}` would itself be filled in.
  - No prompt does today. It would be cleaner to fill in the ticket
    prompt last. Accepted as is.
