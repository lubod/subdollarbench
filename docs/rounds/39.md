# Round 39: Run is a page from the Board, Live is an overlay

Status: ready 3629a827378e
Opened: 2026-10-28, base `round-39-open`
Branch: `round39`
Rules: `2026-10-19.42` (unchanged: GUI only, no graded path)

## Why

The operator wants the console simpler (2026-10-27): Live should open
only while a cell is running, and Run only from the Board.

Today there are four tabs (`src/web/index.html:1092-1096`):

- **Run** with nothing selected says "Select a run on the Board"
  (`:1103`), so `applyHash` falls back to the live cell or the newest one
  (`:1799-1804`). It is a detail view acting as a tab.
- **Live** is empty most of the time, as no cell is running. It is
  also, today, the only place a finished cell's log can be read:
  `renderLive` falls back to the open run, then the newest cell
  (`:2079-2088`), and the Run view has no link to it (the only `#live`
  links are the launcher's lock notes, `:2584`, `:2958`).

The reviewer's analysis (in chat, 2026-10-27) agreed with both goals
but not with modals:

- Live is watched for hours, so it needs the full height.
- Run is the deepest view, and it links to other runs (prev/next, the
  chained phase's `from …`, `:2865-2872`). Modals would stack or break
  the back button.
- Both must keep shareable URLs.

The operator chose the reviewer's alternatives (D1, D2).

This replaces part of `gui-spec.md` (the operator's file, which this
round does not edit): the four tabs of §3, and §4.2's "`#run` with no
id opens the live cell" rule.

## Operator decisions

Decided 2026-10-27 ("draft 39 a a").

- **D1 (Live) = (a):** a full-height overlay above the current view, with
  its own URL, opened by a header button that shows only while a cell is
  running or stalled. Rejected: (b) a modal dialog.
- **D2 (Run) = (a):** a drill-down page reached from a Board row, with
  `‹ Board` to go back. Rejected: (b) a modal.

## Items

### F1. Run is a page, not a tab (D2)

- Remove the Run tab button. The tab bar is Board and Admin.
- A Board row still opens `#run/<id>`. The page starts with `‹ Board`
  (a link to `#board`), then today's Run content.
- Going back (`‹ Board`, the browser's back button, or Esc when no
  overlay is open) shows the Board at the scroll position it had.
- prev/next and the chained `from …` link stay in-page hash changes: no
  stacking, and back steps through them as today.
- A bare `#run` (old links) shows the Board.

- [x] Routing is one pure function of the hash and the Board cells

### F2. Live is an overlay (D1)

- Remove the Live tab. `#live` and `#live/<id>` open a full-height
  overlay above whatever view was open (Board, Run or Admin stays
  rendered underneath).
- Close with ✕, Esc or the browser's back button. Closing restores the
  previous hash, so the view underneath is unchanged.
- The overlay is `role="dialog"` with a label. Focus moves into it on
  open and back to the opener on close. Below 700 px it fills the
  screen. Nothing scrolls the page sideways at 390 px.
- Its content is today's Live: card, chips, stream, follow and jump.
- Polling runs only while the overlay is open (today: while the hash
  starts with `#live`, `:2111`).

Acceptance:
- [x] No `data-tab="live"`; the overlay element carries
  `role="dialog"` — test: the console marker test.
- [x] Routes: `#live/<id>` → overlay for `<id>` over the previous view;
  `#live` → overlay for the running or stalled cell, or, with none,
  no overlay and the Board — test: `r39_f1_route_table`.
- [ ] Esc closes the overlay and the view underneath keeps its state —
  check: the reviewer's browser check.

### F3. The header Live button

- Shown only while a Board cell is `running` or `stalled`. It is a
  link to `#live/<id>`.
- Text while running: `▶ Live · t<ticket> · <turn>/<max> · $<spent>`,
  from the same live block as the card, so they never disagree.
  Stalled: `Live · stalled`, in the danger colour.
- With no such cell, the button is absent, not disabled.
- Several running cells: the button opens the first; the overlay has a
  picker (gui-spec.md §4.3 already asks for one).

Acceptance:
- [x] The button's visibility and text are one pure function of the
  Board cells (for example `liveButton(cells)` → null or `{id, text,
  stalled}`), tested under node: none running → null; one running →
  its id and text; one stalled → stalled text — test:
  `r39_f3_live_button`.

### F4. Finished cells keep their console

The Live tab's fallback was the only way to read a finished cell's log.
Without it:

- The Run page gets a `Console` button that opens `#live/<id>` for
  that cell, running or not.
- For a cell that is not running, the overlay's card says it is finished
  (or stalled), and polling stops after the log is loaded (as today,
  `:2070`).
- If the cell finishes while its overlay is open, the overlay stays
  open. The card changes to finished, with `open its Run ›`.

Acceptance:
- [x] The Run page has a `Console` link to `#live/<id>` — test: the
  console marker test, plus `r39_f1_route_table` for a finished cell's
  id.
- [ ] A finished cell's console loads with no polling afterwards —
  check: the reviewer's browser check (the request count stays flat).
