# Round 82: opencode is the graded harness

Status: draft
Opened: not yet, base `round-82-open`

## Why

Operator, 2026-11-13 ("A"; `docs/DECISIONS.md` #31): the `.47` careers
run on opencode. On the free-model comparison, phase 1 scored 10.0 in
431 requests and 59 min on opencode against 8.8 in 848 requests and
90 min on omp. Round 79 made opencode safe to compare but left it
smoke-only (`scripts/sql-cell.sh:46-50`), with omp the default in
every entry point (`scripts/sql-cell.sh:330`, `scripts/grid.sh:49`,
`scripts/model-check.sh:89`, `src/main.rs:837`,
`src/main_campaign.rs:1591`). The operator also decided, at round 79's
merge, that sessions are titled by the career model (R79-9); and round
79 carried R79-7, R79-10 to R79-14 and R79-17 to "the next opencode
round".

**Order:** branch `round82` from master **after round 81 merges**, not
from `round-82-open`, and say so in the notes.

## Items

### F1. opencode is the default and the only official harness

- Every entry point defaults to `opencode` (the five places above).
- An official cell or grid on `omp` is refused with a clear line, as
  opencode was before; `omp` stays runnable for smoke cells and
  rehearsals. The `.47` ledger rows say `opencode`.
- `scripts/grid.sh --harness` accepts only `omp` or `opencode` (R79-7),
  and its usage text lists it for the grid, not only `--rehearsal`.

Acceptance:
- [ ] Official opencode accepted, official omp refused, smoke omp
      accepted — check: `scripts/sql-cell.sh --self-test`
- [ ] `--harness rust` is refused; the default ledger row says
      `opencode` — check: `scripts/grid.sh --self-test`

### F2. Every request goes to the career model, pinned

opencode may call a second, "small" model (titles, summaries); in the
model check it billed `openai/gpt-6-luna` (round 79 notes, R79-9). The
runner passes `--title` (`src/sandbox/opencode.rs`, the command build),
which may or may not stop that call.

- Set opencode's small model to the career model, with the same
  per-model `body.provider` pin, in the one config function
  (`variant_config_json`), and in `model-check.sh`'s
  `opencode_config_json`.
- Prove it with round 79's stub (`scripts/opencode-stub.py`): a run
  through the runner's config, with `--title` and without, sends
  **every** request with the career model id and the pin; the stub's
  request log is the evidence.

Acceptance:
- [ ] The stub's request log for a two-turn session holds only the
      career model, each request with the pin — test:
      `r82_f2_one_model_per_session` (live, Docker, the stub; no network)
- [ ] The model check fails if its session makes a request to another
      model (a self-test case with a canned log) — check:
      `scripts/model-check.sh --self-test`

### F3. The effort setting reaches the request (R79-13)

The runner sends `-m provider/model#<variant>` with `low`/`high`/`max`
variants in `OPENCODE_CONFIG_CONTENT`; round 79 found that the
`providers` options shape was ignored for the pin, so the variants may
be ignored too. Prove what reaches OpenRouter with the stub, and fix
the shape if needed.

Acceptance:
- [ ] Through the stub, `#low` and `#high` produce request bodies with
      `reasoning.effort` `low` and `high` — test:
      `r82_f3_effort_reaches_the_request` (live, Docker, the stub)
- [ ] The notes say what the `.46` and earlier opencode smoke runs sent
      (whether effort applied there), from the same evidence

### F4. Health reads opencode correctly (R79-10, R79-14, R79-17)

- **R79-14:** the runner's event-to-line mapping becomes one function
  (out of the run loop), `scripts/capture-opencode-lines.sh` calls it
  (through a small binary or test entry), and each fixture under
  `src/campaign/fixtures/health/opencode-*` gets its raw `--format json`
  events beside it; a test turns the events into the fixture.
- **R79-10:** a turn still open at the next `[LIVE] Agent initialized`
  or `[LIVE] Turn N started` is judged (empty or not, its time) before
  the new one opens.
- **R79-17:** `saw_429` is per session, so one 429 doesn't make every
  open turn of the phase count as rate-limited.

Acceptance:
- [ ] Each fixture equals the mapping of its raw events — test:
      `r82_f4_fixtures_match_events`
- [ ] A turn interrupted by a new session is counted once, with its
      time; a 429 in one session leaves another session's retries
      uncounted — test: `r79_f2_health_reads_opencode_stub_lines`
      (extended) or a new `r82_f4_*` test, each assertion seen failing

### F5. The model check is safe to run (R79-11, R79-12)

- **R79-12:** the opencode model check measures the key's usage delta,
  so it refuses to start while any `sdb-*` unit, cell or grid is running
  on the same key, and says which.
- **R79-11:** `r79_f1_run_dir_holds_no_key`'s key assertion can't fail
  (the mount args never see the key); replace it with one that can: the
  runner's real `docker run` arguments for a run carry the key only as
  `-e OPENROUTER_API_KEY` and in no file under the run dir.

Acceptance:
- [ ] The model check refuses beside a running cell (a fake unit in the
      self-test) — check: `scripts/model-check.sh --self-test`
- [ ] The key test is seen failing with the key written to a run-dir
      file — test: `r79_f1_run_dir_holds_no_key` (rewritten)
