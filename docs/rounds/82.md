## Items

### F1. opencode is the default and the only official harness

- Every entry point defaults to `opencode` (the five places above).
- An official cell or grid on `omp` is refused with a clear line, as
  opencode was before; `omp` stays runnable for smoke cells and
  rehearsals. The `.47` ledger rows say `opencode`.
- `scripts/grid.sh --harness` accepts only `omp` or `opencode` (R79-7),
  and its usage text lists it for the grid, not only `--rehearsal`.

Acceptance:
- [ ] Official opencode accepted, official omp refused, smoke omp
      accepted — check: `scripts/sql-cell.sh --self-test`
- [ ] `--harness foo` is refused; the default ledger row says
      `opencode` — check: `scripts/grid.sh --self-test`

### F2. Every request goes to the career model, pinned

opencode may call a second, "small" model (titles, summaries); in the
model check it billed `openai/gpt-6-luna` (round 79 notes, R79-9). The
runner passes `--title` (`src/sandbox/opencode.rs`, the command build),
which may or may not stop that call.

- Set opencode's small model to the career model, with the same
  per-model `body.provider` pin, in the one config function
  (`variant_config_json`), and in `model-check.sh`'s
  `opencode_config_json`.
- Prove it with round 79's stub (`scripts/opencode-stub.py`): a run
  through the runner's config, with `--title` and without, sends
  **every** request with the career model id and the pin; the stub's
  request log is the evidence.

Acceptance:
- [ ] The stub's request log for a two-turn session holds only the
      career model, each request with the pin — test:
      `r82_f2_one_model_per_session` (live, Docker, the stub; no network)
- [ ] The model check fails if its session makes a request to another
      model (a self-test case with a canned log) — check:
      `scripts/model-check.sh --self-test`

### F3. The effort setting reaches the request (R79-13)

variants in `OPENCODE_CONFIG_CONTENT`; round 79 found that the
`providers` options shape was ignored for the pin, so the variants may
be ignored too. Prove what reaches OpenRouter with the stub, and fix
the shape if needed.

Acceptance:
- [ ] Through the stub, `#low` and `#high` produce request bodies with

      `r82_f3_effort_reaches_the_request` (live, Docker, the stub)
- [ ] The notes say what the `.46` and earlier opencode smoke runs sent
      (whether effort applied there), from the same evidence
