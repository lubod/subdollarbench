## Items

### F1. No two tests share a host port or a temp path

- **Ports:**
  - Give each test that starts containers its own worker number, or
    move the pair that meets on 15380. Either way, add a check.
  - The check is a unit test that lists every test's worker and task
    (one table in `src/pipeline.rs` tests, or wherever the workers are
    defined). For each one it computes every host port the test can
    bind:
    - the candidate's `worker_port(task base, w)`;
    - the references: ref-redis 6380, ref-http 8081, ref-sql 5481;
    - pg at +50 and HA at +60..62;
    - the proxy pool `PROXY_UPSTREAM_PORTS` plus the worker offset.
  - It fails, naming both tests and the port, when two tests that can
    run at the same time would bind the same port. Tests serialized by
    `SQL_PERF_LIVE` may share ports with each other, but not with tests
    that aren't serialized.
  - Ports from `free_port()` (`src/sandbox/docker.rs:2608`) are outside
    this check. They're 20000-59980, and the worker ports stay below
    20000; the check asserts that too.
- **Temp paths:** the two compliance tests (`src/verifier/compliance.rs:1530`,
  `:1550`) get distinct directory names. Grep for any other
  `temp_dir().join(format!(...process::id()))` name used by more than
  one test, and fix it the same way. The reviewer found only this pair.
  The `subdollar-ref-sql-src-<instance>` names are per instance, which is
  fine.

Acceptance:
- [ ] No two concurrent tests bind the same host port — test: the new
  port-table test (name it `r37_f1_...`). It fails on today's table,
  because of 15380.
- [ ] Every new test that starts containers has to be in the table —
  check: say under Implementer notes how a forgotten one is caught
  (for example, the table test greps the `let worker = N` lines in
  `src/pipeline.rs`).
- [ ] The compliance tests use distinct directories — test: both pass
  together, 20 times, in one `cargo test compliance` loop. Quote the
  count.

### F2. The upstream pool is ready before it's used

- After `docker run -d`, `start_upstream_on` probes
  `http://127.0.0.1:<port>/` until it serves the upstream's marker body
  (`upstream_marker_body(idx)`) or a bounded timeout passes (for
  example 30 s). On a timeout, return an error that names the upstream
  and the port.
- The restart path (`src/sandbox/docker.rs:1182`) gets the same probe,
  unless a caller needs the upstream down. If so, say which caller under
  Implementer notes.
- This changes no grading. The pool belongs to the retired proxy
  campaign (#19), and no sdb-sql stage uses it.

Acceptance:
- [ ] `start_upstream_pool` returns only once every upstream serves its
  marker — test: a live test that checks all 3 respond right after the
  call. `test_pipeline_eval_only_proxy_full_ladder_live` still passes.
- [ ] A port that never serves gives the named error within the timeout —
  test: a unit or live test with a short timeout.
