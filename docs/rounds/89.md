## Items

### F1. The torn tail never cuts into an older commit

The (c) step cuts `crash::torn_tail(&path, 256)` (`src/pipeline.rs:245`),
and `torn_tail` cuts `bytes.min(len / 2)` (`src/verifier/sql/crash.rs:477`),
whatever the victim commit wrote; `changed_file` computes `grew`
(`src/verifier/sql/crash.rs:413-414`) and drops it. A one-row INSERT
grows a statement log by ~40-60 bytes, so the 256-byte cut also tears
the record before it (the last 1000-row bulk INSERT), and a correct
checksummed log loses 1000 rows. The ticket's own prompt
(`campaigns/sdb-sql/stages/5_crash/prompt.md:20-25`) says the cut comes
from "the region your last commit grew" and only the newest statement
may be lost. In haiku's `.48` repair log the agent showed a 300-byte cut
gives exactly 99000/100000.

Fix: cut `min(256, grew, len / 2)` bytes from the file the victim grew;
when it grew nothing tearable, try another victim (the existing retry).

Acceptance:
- [ ] `torn_tail`/the (c) step never cuts more than the victim commit
      grew — test: `r89_f1_cut_never_exceeds_the_commit`
- [ ] A store whose log records are smaller than 256 bytes (a compact,
      checksummed, append-only statement log) passes (c) — test:
      `r89_f1_compact_log_store_passes_the_tear`
- [ ] A store that loses an older committed record across the tear still
      fails (c) — test: `r89_f1_losing_an_older_record_still_fails`
- [ ] Each seen failing

### F3. The model's own words never trip the billing fault

For an opencode `text` event the runner also classifies the model's
prose (`src/sandbox/opencode.rs:257-260`) with the stderr classifier
(`src/sandbox/omp.rs:396-447`), where "rate limit", "too many requests"
or "unauthorized" beside "key/token/auth" is a Fault. A Fault stops the
cell as a harness fault (`src/pipeline.rs:3210-3223`). Ticket 18
(auth, limits) invites exactly that prose. Classify only structured
error events and the raw provider error payload; a 429 under opencode
is rate-limited (transient), not a Fault, unless the session ends on it.

Acceptance:
- [ ] Model text such as "reject unauthorized connections with ERR
      auth", "add a connection rate limit", "too many requests from one
      client" never sets the billing fault — test:
      `r89_f3_prose_never_trips_billing`
- [ ] A real OpenRouter 402 and 401 error event still trip, and a 429
      the session ends on still ends it as a provider fault — test:
      `r89_f3_real_provider_errors_still_trip`
- [ ] Each seen failing

### F4. Ticket 15's sensitivity check builds the reverted code itself

The scratch copy includes `target/` (`copy_dir_inner`,
`src/campaign.rs:3919`), so a `start.sh` that builds only when the
binary is missing runs the stale, un-reverted binary; and a revert
that doesn't compile counts as "red" or as a FAIL charged to ticket 15
at later tickets (`src/pipeline.rs:791-835`). Exclude `target/` from
the copy, build the reverted copy explicitly with its own time limit,
and treat "the reverted code does not compile" as inconclusive (neither
a pass nor a failure of ticket 15). A coverage measurement that hits its
time limit is an infra error, not a model failure (the timed-out flag is
dropped by `run_workspace_command`, `src/sandbox/docker.rs:1455-1461`).

Acceptance:
- [ ] The reverted copy has no `target/` and is built before it is
      probed — test: `r89_f4_revert_builds_without_the_old_target`
- [ ] A revert that doesn't compile is inconclusive, never a ticket-15
      failure — test: `r89_f4_uncompilable_revert_is_inconclusive`
- [ ] A coverage time-out is reported as an infra error — test:
      `r89_f4_coverage_timeout_is_infra`
- [ ] Each seen failing

## Changes after open

- **2026-11-17, operator: "cap catchup"** (before the implementer
  started). Two items join this round and the `.50` history entry:

  **F6. A catch-up takes only its share of the phase.** Today the
  catch-up's divisor is `runnable_weight_sum + target_weight`
  (`src/campaign.rs:3245`), and `runnable_weight_sum` leaves out the
  phase tickets the target blocks, so when every phase ticket is
  blocked the catch-up gets 100 % of the headroom (minimax `.45`:
  phase 4 scored 0 of 32 after one $0.97 catch-up of ticket 5). The
  divisor becomes the target's weight plus the weight of **every**
  phase ticket not yet run in this phase, blocked ones included, so a
  catch-up gets its tier's share and the rest stays for the phase's own
  tickets if it passes.
  - [ ] Ticket 5's full catch-up before stages 16-20 (all blocked) gets
        2/(2+32) of the headroom, not all of it — test:
        `r89_f6_catch_up_takes_its_share` (seen failing)

  **F7. A ticket a phase never reached is carried to later phases.**
  When a cap or wall stop ends the loop (`src/campaign.rs:3377-3393`),
  the phase tickets that never ran get no outcome, and
  `catch_up_targets` only reads outcomes (`src/campaign.rs:2893`), so a
  later phase never catches them up and everything that needs them is
  skipped for the rest of the career (11 archived phases stopped this
  way). Record them as not reached (a new outcome, or Skipped) in
  `ladder_state`; later phases treat them as catch-up targets and the
  phase hints name them.
  - [ ] A phase stopped at the cap with tickets 11-15 unrun: the next
        phase's catch-up targets include them, and ticket 16 is no
        longer blocked once 11 passes — test:
        `r89_f7_unreached_ticket_is_caught_up_later` (seen failing)
