## Why

The 2026-11-17 audit (four read-only reviews) produced fixes now in
rounds 89 and 90; these are the grading leftovers, plus the two findings
the round-89 review recorded. Each is small, each has a regression test,
and a single bump covers them with round 91's faster bar.

- **R89-2 (from the round-89 review):** the (c) baseline is taken once at
  the step's start, so after a retry `grew` includes the earlier
  victims' growth and the cut can reach an earlier, owed victim.
- **R89-1:** when every reverted copy fails to compile, ticket 15 passes
  with its sensitivity unproven.
- The coverage measurement keeps only `profile.test` artifacts, so lines
  exercised only through the server binary that integration tests spawn
  are not counted; the prompt promises "your crate's own tests".
- `copy_dir_inner` follows symlinks and can block on a FIFO in a
  candidate's workspace, copying a host file's content into the scratch
  tree and back into the model's feedback.
- A failure to come back on the real store after a scenario is charged
  to that scenario's ticket (a 20 s restart budget).

### F1. A retry's tear is bounded by its own victim

The (c) cut is at most what the victim commit itself grew, even after a
retry: re-snapshot before the retry so the earlier victims aren't
counted, or cap the cut at the last victim's own growth.

Acceptance:
- [ ] After a first attempt that tears nothing, the second attempt's cut
      never exceeds its own victim's growth — test:
      `r92_f1_retry_cut_is_bounded_by_its_own_victim` (seen failing)
- [ ] The compact-log reference and the rewritten-log reference still
      pass stage 5

### F2. Ticket 15 needs one conclusive revert

If every candidate revert can't build (or can't answer SELECT 1), the
sensitivity check proves nothing; ticket 15 fails with
`sensitivity is inconclusive ... no conclusive revert` instead of
passing, and the failure is marked `harness`/inconclusive so the model
gets the whole check to do rather than a silent pass.

Acceptance:
- [ ] Every revert inconclusive: ticket 15 doesn't pass — test:
      `r92_f2_no_conclusive_revert_cannot_pass` (seen failing)
- [ ] One conclusive revert still decides sensitivity

### F3. Coverage includes the binaries tests spawn

The report merges `--object` for the server binaries that the tests
spawn, not only the test binaries, so black-box tests count. The set is
derived from the same `cargo test` artifacts (not the candidate's
`target/`); the `/workspace/src/` filter and the test exclusions stay.

Acceptance:
- [ ] A fixture whose only integration test runs the server as a
      subprocess counts its `src/` lines — test:
      `r92_f3_spawned_server_lines_count` (seen failing)
- [ ] A file tested both by unit tests and through the server is counted
      once

### F4. A scratch copy never follows a symlink or a FIFO

Use the same regular-file-only walk as `crash::copy_tree` for
`copy_dir_inner`: symlinks, FIFOs and other non-regular files are
skipped and logged, never copied as content.

Acceptance:
- [ ] A workspace symlink pointing at a host file isn't copied into the
      scratch tree (the file's content never leaves) — test:
      `r92_f4_symlinked_workspace_is_not_copied_out` (seen failing)

### F5. A restart failure after a scenario is not the scenario's fault

Label it `restart_after_<scenario>` and attribute it to the store's
restart (ticket 4) rather than the scenario's own check; log the
container's state and last lines at the 20 s deadline.

Acceptance:
- [ ] A restart that misses its deadline after the memory scenario
      reports `restart_after_memory` and is attributed to ticket 4 — test:
      `r92_f5_restart_failure_named_by_scenario` (seen failing)
