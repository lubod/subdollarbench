## Why

Three problems on 2026-11-08/09 left clear traces in data the harness
already had, and were found by hand, hours or days late
(`docs/DECISIONS.md` #28, #29):

- **Minimax's provider broke tool calls** on 8-76 % of turns
  (`gmicloud/fp8`). Its first phase showed it within minutes; it was
  found the next day, after $8 and a published result.
- **Hy4 resolved to another model** in the sandbox's omp. Found by a
  manual pre-check, after the grid was armed.
- **The reference server (`ref-sql`) drops out** for short spells during
  agent sessions: 19-27 % of the OpenAI models' reference queries were
  refused, 1-4 % of the others'. Never noticed.

Round 68 adds the pre-grid model check with a tool call (F3) and a
post-phase provider-fault check (F5). This round adds the rest: health
numbers for every phase, a live check that stops a bad phase early, a
canary before the other lanes start, an audit that gates publishing,
and the `ref-sql` fix.

## Items

### F1. Health numbers for every phase

- Each phase records, in its `campaign.json` / rollup:
  - `tool_errors`: agent turns whose tool call failed at the provider
    (`provider stream ended with an error`, `Upstream error from`), and
    `turns`;
  - `ref_refused` / `ref_queries`: the agent's commands that reached
    `ref-sql` and those refused (as counted in DECISIONS #29's review);
  - `turn_secs_p50` / `turn_secs_max`: seconds per agent turn;
  - `empty_responses`: turns with no content and no tool call;
  - `billed_ratio`: billed / list (round 67 records both).
- The counting lives in one place that the live check (F2), the audit
  (F3) and the GUI (F5) all call. Real logs are the fixtures.

Acceptance:
- [ ] Test `r74_f1_health_from_logs`: the counts from saved excerpts of
  real logs: a minimax 2026-11-08 phase (tool errors 25 of 73 turns), a
  luna-pro phase with `ref-sql` refusals, a clean deepseek phase (all
  zero).
- [ ] The numbers for every published phase in the notes (a table per
  model), matching DECISIONS #29's review.

### F2. A live check, and a canary before the other lanes

- **Live check:** while a phase runs, `grid.sh` reads its health numbers
  every 2 minutes. It **stops the phase** (the cell is killed, the run is
  marked `provider_fault` and hidden, the grid holds with the reason)
  when, after at least 20 turns:
  - tool errors are over 2 % of turns and at least 5; or
  - empty responses are over 5 % of turns and at least 5.
  It **warns** (log line and GUI, no stop) when the median turn is over
  180 s or `ref-sql` refusals pass 10 % of reference queries.
- **Canary:** in a paid grid, lane 1 starts alone. The other lanes start
  only when its live check has passed 30 turns cleanly; if it stops, no
  other lane starts.
- Round 68 F5's post-phase check stays as the backstop.

Acceptance:
- [ ] `scripts/grid.sh --self-test`: a phase that replays the minimax log
  is stopped by the live check within its first 30 turns; a clean replay
  isn't; with a stopped canary, lanes 2 and 3 never start; with a clean
  canary, they start after 30 turns.
- [ ] The time and cost the canary would have saved on minimax's
  2026-11-08 grid, from its logs, in the notes.

### F3. An audit before publishing

- `scripts/run-audit.sh` reads every run the export would publish and
  reports, per model:
  - phases over F2's thresholds (each a **finding**);
  - **every phase 1 of a model at 0 points**;
  - **a rerun much worse than an earlier attempt** of the same model
    (median career points under half of the earlier attempt's, where an
    earlier attempt exists, hidden or not);
  - `billed_ratio` over 1.25 in any phase.
- `publish.sh` refuses an export with an open finding. A finding is
  closed by a line in `docs/audit-waivers.txt`: the model, the finding,
  who decided and why (the operator decides; the reviewer writes it).
- It also runs at the end of every grid and prints its summary to the
  grid's log.

Acceptance:
- [ ] `scripts/run-audit.sh --self-test` on fixtures: the minimax
  2026-11-08 rerun raises tool errors, all-zero phase 1 and worse-than-
  earlier-attempt; the 6 published models raise none.
- [ ] `scripts/publish.sh --self-test`: an open finding refuses, a
  waived one passes, and the waiver line is printed.

### F4. The reference server stays reachable (investigate, then fix)

- **Measure first:** during a session, probe `ref-sql` from the run
  network every 5 s (a small sidecar or `docker run --network ... nc`),
  and log each change between up and down with its time.
- **Find the cause** from those logs and the container's own state
  (exit code, restart count, OOM kill, its log). Candidates: a query
  that crashes it, followed by a restart; a resource limit; the
  harness restarting it between checks.
- **Fix it** so `ref-sql` is reachable for the whole session, and show
  zero refusals from the probe on a $0 rehearsal with 3 lanes at once.
  (A rehearsal has no agent; if a query crashes the reference, a
  scripted client sends it.)
- If the fix is in a grader path, ask under **Spec questions** first
  (see "Where the code goes").

Acceptance:
- [ ] The cause, with the evidence (log lines, container state), in the
  notes.
- [ ] A test or self-test that reproduces the cause and passes with the
  fix, seen failing without it.

### F6. A provider fault reruns its phase (R68-1)

- Today (round 68 F5, `scripts/grid.sh`): after a `provider_fault` hold
  is released, the lane abandons that career and goes on to the next, so
  the career ends incomplete and is never published.
- Instead: after the release, the lane **reruns the faulted phase in the
  same career**, from the same chain point (the previous phase's end),
  as a fresh cell. The faulted cell stays hidden, with its reason; the
  rerun is the career's phase.
- A phase that faults **twice** in a row (two holds) stops that lane's
  career and writes a STOP line that names both faults; the operator
  decides (a new pin, or give up the model).
- F2's live stop uses the same path: a phase stopped mid-run for a
  provider fault is rerun after the release in the same way.
- The ledger shows both rows (the faulted one `provider_fault`, the
  rerun `ok`), and the career's cost includes the faulted cell's spend.

Acceptance:
- [ ] `scripts/grid.sh --self-test`: a faulted phase 2, a release, and the
  rerun continues the same career from phase 1's end (its chain source is
  phase 1's run, not the faulted one); a second fault stops the career
  with the STOP line; the ledger has both rows and the spend adds up.
