## Why

Operator, 2026-11-11: before the whole sdb-sql rerun the rules move to
`.47` with a Go-only stack, and the harness may move from omp to
opencode ("test opencode first"). A harness change is a change to what
the candidate sees, so it is decided once, before the rerun, on a small
paid comparison. Today the opencode harness can't run such a cell:

- It mounts the host's `~/.config/opencode` and `~/.local/share/opencode`
  into the sandbox (`host_opencode_dirs`, `src/sandbox/opencode.rs:354`;
  DECISIONS #25). The data dir holds every opencode session on this
  host, including the implementer's work on the grader.
- The run-health counter, the rate-limit classifier
  (`classify_billing_error`, `src/sandbox/omp.rs:284`) and
  `scripts/model-check.sh` were built and calibrated on omp's output.

This round only makes the opencode path safe and measurable. It doesn't
choose the harness and doesn't change the grid's default (`omp`).

## Items

### F1. A per-run opencode config and data dir, with auth only

The opencode candidate gets a fresh config dir and data dir per run,
holding only what the session needs to reach OpenRouter (the key through
the environment or a generated auth entry; the pinned provider; the
pinned version). Nothing under the host's home is mounted. The dirs are
removed, or kept inside the run dir without the key, when the run ends.

Acceptance:
- [x] The container arguments mount no path under the host's `~/.config/opencode` or `~/.local/share/opencode` — test: `r79_f1_no_host_opencode_mount`
- [x] A sentinel file in the host's data dir is not readable from the candidate's container — test: `r79_f1_host_sessions_invisible` (live, Docker)
- [x] No plugin, command or advisor config reaches the candidate; the key is in no file left in the run dir — test: `r79_f1_run_dir_holds_no_key`

### F2. Run health and faults read an opencode session

The phase health numbers (turns, turn times, tool errors, `ref-sql`
queries and refusals, empty responses, `rate_limited`) and the billing
fault (402/401 at once; a 429 only when it ends the session) come out
the same way for an opencode run as for an omp run. Calibrate on a real
opencode `live.log`, not an invented one; say in the notes which run.

Acceptance:
- [x] A recorded opencode `live.log` yields non-zero turns and turn times, and its tool calls to `ref-sql` are counted — test: `r79_f2_health_reads_opencode_log`
- [x] An opencode 402 trips the fault; a retried 429 is counted, not a fault — test: `r79_f2_opencode_billing_signals`, `r79_f2_health_reads_opencode_stub_lines` — proved on the stub's captured opencode 2.0.24 lines: the 402 and the exhausted 429 are faults, the exhausted run's 9 retries are `rate_limited`, the broken stream is one `tool_error` and not a billing fault. A 429 that succeeds on retry is invisible in opencode 2.0.24's output (one `[LIVE] Turn` line, one answer), so it is neither counted nor a fault; see **Spec questions**.

### F3. The model check runs through the sandbox's opencode

`scripts/model-check.sh --harness opencode <model>`: the exact model id
sent and served, the pinned provider, the bill within 1.25x, and a
tool-call round trip, with its own record
(`model-check-opencode-<model>.txt`). The omp check and its records are
unchanged.

Acceptance:
- [x] The self-test covers pass, wrong provider and over-bill for `--harness opencode` — check: `scripts/model-check.sh --self-test`
- [x] The cost the harness computes for an opencode session matches OpenRouter's bill within 1.25x on a canned session — test: `r79_f3_opencode_cost_matches_bill`

### F4. A comparison cell can run, and stays off the board

`scripts/sql-cell.sh` and `scripts/grid.sh` take `--harness opencode`
(or the cell's existing variable) for **smoke** cells only; an official
cell on opencode is refused until a later round allows it. Each run and
ledger row records its harness. A comparison run is hidden from the
public export.

Acceptance:
- [x] An official cell with the opencode harness is refused with a clear line — check: `scripts/sql-cell.sh --self-test`
- [x] The ledger and `campaign.json` name the harness; the export skips comparison runs — test: `r79_f4_comparison_runs_are_hidden`
- [x] A $0 rehearsal with the opencode harness completes 4 phases — record in the notes (needs a gap; no grid runs now)

## Spec questions

- **R79-2: the successful 429 retry is invisible.** opencode 2.0.24
  prints one `[LIVE] Turn` line for a request that gets a 429 and then
  succeeds (the stub logged three HTTP requests; the log has one turn),
  so the retry cannot be counted. An exhausted run prints one `[LIVE]
  Turn` per attempt and the final 429; the parser counts the 9 extra
  turns as `rate_limited` only when a 429 line is present, so a
  stream-error retry stays a `tool_error`. Is the exhausted-run count
  enough for the box?
- **R79-4: the named free model is geo-blocked here.**
  `thinkingmachines/inkling-2-small:free` answers 403 "This model is not
  available in your region." for both the wrong (`novita`) and right
  (`thinkingmachines/nvfp4`) pins from this host; OpenRouter's endpoints
  API lists one endpoint, `thinkingmachines/nvfp4`. The $0 live proof
  uses `baidu/ernie-5.5-flash-preview:free` (wrong pin 404, right pin
  "ok"), and the stub's request log proves the exact inkling id's
  per-model body pin. Is that enough, or does the reviewer want another
  host or model?
- **R79-2: the capture script mirrors the runner's line mapping.**
  `scripts/capture-opencode-lines.sh` maps the stub's `--format json`
  events to the runner's `[LIVE]`/`[ACTION]`/`[RESPONSE]`/`[TELEMETRY]`/
  `[LOG]`/`[STDERR]` lines (the runner's loop is not a separate
  function). The fixtures are what a cell writes; a full
  `OpenCodeRunner`-against-the-stub integration is not in this round. Is
  the fixture plus the `error_event_billing_reason` test enough?
- **R79-9: the free-model run's title call is priced.** opencode's
  title generation uses `openai/gpt-6-luna` even when the career model is
  free; the free-model check's OpenRouter usage delta was $0.00013280.
  The main model was free; the title call is the only spend. Should the
  runner set `small_model` to the career model (or disable titles) in a
  later round?
