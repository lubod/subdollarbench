Status: ready 2f0096e

## Why

Operator, 2026-11-11: before the whole sdb-sql rerun the rules move to
`.47` with a Go-only stack, and the harness may move from omp to
opencode ("test opencode first"). A harness change is a change to what
the candidate sees, so it is decided once, before the rerun, on a small
paid comparison. Today the opencode harness can't run such a cell:

- It mounts the host's `~/.config/opencode` and `~/.local/share/opencode`
  into the sandbox (`host_opencode_dirs`, `src/sandbox/opencode.rs:354`;
  DECISIONS #25). The data dir holds every opencode session on this
  host, including the implementer's work on the grader.
- The run-health counter, the rate-limit classifier
  (`classify_billing_error`, `src/sandbox/omp.rs:284`) and
  `scripts/model-check.sh` were built and calibrated on omp's output.

This round only makes the opencode path safe and measurable. It doesn't
choose the harness and doesn't change the grid's default (`omp`).

## Items

### F1. A per-run opencode config and data dir, with auth only

The opencode candidate gets a fresh config dir and data dir per run,
holding only what the session needs to reach OpenRouter (the key through
the environment or a generated auth entry; the pinned provider; the
pinned version). Nothing under the host's home is mounted. The dirs are
removed, or kept inside the run dir without the key, when the run ends.

Acceptance:
- [x] The container arguments mount no path under the host's `~/.config/opencode` or `~/.local/share/opencode` — test: `r79_f1_no_host_opencode_mount`
- [x] A sentinel file in the host's data dir is not readable from the candidate's container — test: `r79_f1_host_sessions_invisible` (live, Docker)
- [x] No plugin, command or advisor config reaches the candidate; the key is in no file left in the run dir — test: `r79_f1_run_dir_holds_no_key`

### F2. Run health and faults read an opencode session

The phase health numbers (turns, turn times, tool errors, `ref-sql`
queries and refusals, empty responses, `rate_limited`) and the billing
fault (402/401 at once; a 429 only when it ends the session) come out
the same way for an opencode run as for an omp run. Calibrate on a real
opencode `live.log`, not an invented one; say in the notes which run.

Acceptance:
- [x] A recorded opencode `live.log` yields non-zero turns and turn times, and its tool calls to `ref-sql` are counted — test: `r79_f2_health_reads_opencode_log`
- [x] An opencode 402 trips the fault; a retried 429 is counted, not a fault — test: `r79_f2_opencode_billing_signals`

### F3. The model check runs through the sandbox's opencode

`scripts/model-check.sh --harness opencode <model>`: the exact model id
sent and served, the pinned provider, the bill within 1.25x, and a
tool-call round trip, with its own record
(`model-check-opencode-<model>.txt`). The omp check and its records are
unchanged.

Acceptance:
- [x] The self-test covers pass, wrong provider and over-bill for `--harness opencode` — check: `scripts/model-check.sh --self-test`
- [x] The cost the harness computes for an opencode session matches OpenRouter's bill within 1.25x on a canned session — test: `r79_f3_opencode_cost_matches_bill`

### F4. A comparison cell can run, and stays off the board

`scripts/sql-cell.sh` and `scripts/grid.sh` take `--harness opencode`
(or the cell's existing variable) for **smoke** cells only; an official
cell on opencode is refused until a later round allows it. Each run and
ledger row records its harness. A comparison run is hidden from the
public export.

Acceptance:
- [x] An official cell with the opencode harness is refused with a clear line — check: `scripts/sql-cell.sh --self-test`
- [x] The ledger and `campaign.json` name the harness; the export skips comparison runs — test: `r79_f4_comparison_runs_are_hidden`
- [x] A $0 rehearsal with the opencode harness completes 4 phases — record in the notes (needs a gap; no grid runs now)

### Blockers

- **R79-1 (F2): every opencode session counts one false empty
  response.** `health_from_live_log`'s new `[LIVE] Turn N started`
  branch (`src/campaign/health.rs`) tests `!has_response && !has_tool`
  at the **start** of a turn; omp's `[BENCH-POLICY] turn=` marker comes
  at the end of one. On `Turn 1 started` both flags are still false, so
  the fixture itself yields `empty_responses == 1` for a healthy
  session, and the last turn is never judged.
  `r79_f2_health_reads_opencode_log` doesn't assert the field. A phase
  has one session per ticket and per resume, and `severity()` turns red
  at 5 empties above 5 % of turns, so a healthy opencode phase can be
  marked a provider fault, hidden, and hold the grid. The first turn
  time is also always 0 s (start to `Turn 1 started`). Judge a turn at
  its end (the `[TELEMETRY] turn=` line is there) and assert
  `empty_responses == 0` on the fixture, plus a case with a truly empty
  turn.
- **R79-2 (F2): the rate-limit and tool-error counters still match only
  omp's lines.** `rate_limited` needs a `[STDERR]` line with
  `Retrying (` (omp's retry text), and `tool_errors` needs omp's two
  phrases. `r79_f2_opencode_billing_signals` feeds the classifier an
  omp-shaped string, so the box "a retried 429 is counted, not a fault"
  is proved for omp again, not for opencode. The fixture is a two-turn
  probe (`ses_r79probe`) in which `ref-sql` didn't resolve, so the
  refusal path and the error paths have no opencode evidence at all.
  Wanted: what opencode 2.0.24 really prints for a retried 429 and for
  a provider stream error (a local stub endpoint that answers 429 then
  200 costs nothing), a fixture with those lines, and the counters
  reading them. If that can't be produced at $0, say so under **Spec
  questions**.
- **R79-3 (F1, F3, F4): four new tests can't fail.**
  `r79_f1_host_sessions_invisible` builds its own `docker run` mounts
  from `prepare_run_dirs`; it never uses `opencode_mount_args` or the
  runner's command, so it passes on the old code too (the notes'
  "READABLE" was a manual run). `r79_f1_run_dir_holds_no_key` looks for
  a key string that nothing in the test ever hands to production code
  (its dir-removal half is real). `r79_f3_opencode_cost_matches_bill`
  exercises `add_step`, which this round didn't change, against a
  constant. `r79_f4_comparison_runs_are_hidden` writes the harness into
  `campaign.json` itself and then reads it back, and the hiding is the
  existing smoke rule; no production line in `src/report/grid.rs`
  changed. The notes give a seen-failing line for three tests only and
  no record under `sdb-gates/seen-*`. Each named test needs a
  production path it guards and a seen-failing record
  (`scripts/seen-failing.sh`); where the behaviour already existed, say
  so in the notes instead of adding a test that can't fail.
- **R79-4 (F3): the upstream provider is not pinned and not checked.**
  omp sends `model@provider` (`omp_task_args`, `src/sandbox/omp.rs`),
  which sets OpenRouter's `provider.only`. The opencode runner passes
  the model "untouched" (`src/sandbox/opencode.rs`, the comment above
  the command build) and never calls `provider_for_model`; the model
  check accepts `providerID == "openrouter"`, which is true for every
  OpenRouter call. So an opencode career can be served by a different
  endpoint than the omp career it is compared with: another
  quantisation, another price. The item said "the pinned provider"; the
  notes' **Limit** paragraph should have been a spec question. Wanted:
  the pin sent through opencode (its OpenRouter provider options, per
  model, in the same `OPENCODE_CONFIG_CONTENT`), and the served
  endpoint verified from OpenRouter's side (the generation or activity
  API, as the omp check does), or a spec question showing why not.
- **R79-5 (F3): the opencode bill check doesn't check the bill.** (a)
  It compares the snapshot with `session_v2.cost`, opencode's own
  figure, not what OpenRouter charged; the item and the omp check use
  OpenRouter's number. (b) The live record reads `0 fresh, 16640
  cached`: `tokens_fresh = max(0, input - cached - write)` assumes
  `tokens_input` includes cache reads, while the step in
  `r79_f3_opencode_cost_matches_bill` (input 125, cache read 5312)
  shows opencode reports them apart. A real session with zero fresh
  input tokens isn't plausible; the clamp hides it. Show the real
  `session_v2` row in the notes and fix the formula; take the bill from
  OpenRouter.
