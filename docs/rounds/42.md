## Why

The operator wants an htop-like console in the CLI (2026-10-27). Some
reasons it fits:

- **The operator works over ssh from iTerm2** and can't easily copy
  between windows. A full-screen view in the same ssh session avoids
  the browser.
- **Today's CLI** shows a running cell only as separate snapshots:
  `status`, `queue`, `log --follow`.

**The data already exists.** The engine API serves everything the Board
shows: `/api/status`, `/api/campaigns` (the board rows, the live block,
the ladder, the stop reason), `/api/campaigns/:id` (the ticket table with
causes) and `/api/campaigns/:id/log` (incremental, `?after=`, filtered by
kind). The TUI is a client of that API, through the same client as
`status` and `queue` (`src/remote.rs`, with the `SDB_UI_TOKEN` bearer).

- **No second implementation** of the ranking, the ticket statuses or
  the causes (`gui-spec.md` §4.1, "one renderer"). The TUI shows what the
  API computed.
- **It works the same** whether the engine or `sql-cell.sh` started the
  cell.

**Why it's graded:**

- The TUI needs `ratatui`. `crossterm` is already in `Cargo.lock`, but
  `ratatui` isn't, and `Cargo.lock` is a graded path.
- So the round needs the full gate, and a 20-pass bar before the next
  published cell.
- That's why it comes **before round 43** (the deletion of the retired
  tasks): round 43's bar then covers both, and calibration waits for
  only one bar.
- Nothing graded changes in behaviour. F1's acceptance checks that the
  only graded file in the diff is `Cargo.lock`.

**Keys:**

- `↑`/`↓` select a cell;
- `Enter` opens its ticket table, `Esc` goes back;
- `Tab` switches the focused pane;
- `v`/`a`/`t`/`s` toggle the log kinds;
- `End` follows the log; scrolling up stops following;
- `?` help, `q` quit.

## Items

### F1. The command, the loop, and a terminal that's always restored

- Add `subdollarbench tui` (D1). Its flags: `--server` (as `status`)
  and `--interval` (seconds, default 2, minimum 1).
- `ratatui` on the `crossterm` backend. Add the one dependency, and
  check the version is at least two weeks old.
- **The loop:** poll `/api/status` and `/api/campaigns` every
  interval, redraw on change and on resize, and read keys without
  blocking.
- **The terminal is restored** on `q`, on Ctrl-C, on an error and on a
  panic (a panic hook leaves the alternate screen and raw mode).
- **When the engine is down,** the header says `engine ● unreachable
  (<error>)` and the poll keeps retrying. No crash.
- **The app state** (`App`: cells, selection, focus, log offset,
  filters, follow) is a plain struct. Keys and API responses update it
  through pure functions, so it can be tested without a terminal.

Acceptance:
- [x] The only graded path in the round's diff is `Cargo.lock`, and
  only `ratatui` and what it pulls in are new in it — check: `git diff
  round-42-open..round42 -- <graded paths>` and the new `[[package]]`
  names in the notes.
- [x] The panic hook restores the terminal — test:
  `r42_f1_panic_restores_terminal` (through a test seam for the restore
  calls).
- [x] An unreachable server renders the header line and no panic — test:
  `r42_f1_engine_unreachable` (ratatui `TestBackend`).

### F2. The cells pane

- One row per `/api/campaigns` entry, in the API's order (it is the
  Board ranking).
- **Columns:** rank, the short model name, the ladder strip (one cell
  per ticket in the status colours: pass, lite, fail, fault, running,
  not reached), points / max, `$`, pts/$, and the state (`run t7 19/24`,
  `stalled since 16:12`, `done · budget cap`).
- Numbers are right-aligned with fixed decimals: $ to 4, points to 1.
- **Narrow terminals:** at 80 columns the strip shrinks to the tickets
  that were reached plus a count, then disappears before the numbers do.
  Nothing wraps.
- **`NO_COLOR`:** the strip uses letters (`P L F X R ·`) instead of
  colours.

Acceptance:
- [x] A fixture of three cells (running, stalled, done) renders the
  expected rows at 120 and at 80 columns — test:
  `r42_f2_cells_pane_render` (`TestBackend`, buffer compared line by
  line).
- [x] The rows' order and points are exactly the API's (no ranking in
  the TUI) — test: `r42_f2_order_is_the_apis`.

### F3. The ticket table (`Enter`)

- For the selected cell, from `/api/campaigns/:id`: every ticket in the
  ladder, attempted or not.
- **Columns:** the ticket and its title; tries (first → repair); lite
  tries; points; `$`; the cause, clamped to the width. The not-reached
  rows give their reason (`skipped: needs 7`, `not reached: budget
  cap`).
- `Enter` on a ticket row shows that row's full cause in a popup.

Acceptance:
- [x] A fixture cell with a passed, a failed-with-cause, a lite and a
  not-reached ticket renders all four with their cause or reason — test:
  `r42_f3_ticket_table_render`.

### F4. The live pane and its log

- **Shown** when the selected cell is running or stalled. For another
  cell, the pane shows its last log page.
- **The header lines come from the live block,** the same one the
  Board's card reads: ticket and round, turn x/max, seconds since the
  last activity (stalled in the danger colour), ticket `$`, and
  campaign `$` against the cap as a gauge. The wall gauge appears only
  when a wall is set.
- **The log** uses `/api/campaigns/:id/log` with `?after=` and the
  kinds filter. It fetches only new bytes, and keeps at most 2,000 lines
  in memory.
- **Default kinds:** verdict and agent, as the console's Live
  (`index.html:1823`). Verdict lines are coloured by pass or fail.
- **Following:** on by default. Scrolling up stops it, and `End`
  starts it again.

Acceptance:
- [x] Two polls, where the second returns 3 new lines after the first
  offset, append exactly those 3 and send `after=<first offset>` — test:
  `r42_f4_log_is_incremental` (a stub client).
- [x] Toggling a kind refetches from offset 0 with the new `kinds=` —
  test: `r42_f4_kind_toggle_refetches`.
- [x] A running fixture renders the gauges, and a stalled one renders
  the stalled text — test: `r42_f4_live_pane_render`.

## Review

**Pre-review** (Claude Code, 2026-10-28, read only, branch head
`ed5686b`, before `ready`: the full gate waits for a gap). **Blockers:
3**, so they can be fixed before the gate runs.

- **R42-1 (blocker): Ctrl-C doesn't quit.** In raw mode Ctrl-C arrives
  as a key event (`KeyCode::Char('c')` with `KeyModifiers::CONTROL`), not
  as SIGINT. The loop passes only `k.code` to `handle_key`
  (`src/tui.rs`, `run`), and `c` is unbound, so Ctrl-C does nothing. F1
  says the terminal is restored on Ctrl-C. Fix: pass the modifiers; Ctrl-C
  quits like `q`. Test: `handle_key` with Ctrl-C returns true; seen
  failing on `e07c74f`.
- **R42-2 (blocker): another cell shows the old cell's log and tickets.**
  Up and Down change `selected` but keep `log`, `log_offset` and
  `tickets`. The next poll asks the new cell for `after=<old offset>`
  (`log_request_path`), so the pane shows the old cell's lines plus
  whatever of the new one's lies past that offset; `set_tickets` runs
  only while `tickets` is empty, so `Enter` on another cell shows the
  first cell's table. Fix: a selection change clears the log, the offset
  and the tickets. Test: select cell A, apply a log page, move to B; the
  log is empty, `log_offset()` is 0 and the next path is `tail=400` for
  B; seen failing on `e07c74f`.
- **R42-3 (blocker): two crosstermes.** F1 asks for one new dependency
  (ratatui and what it pulls in). `Cargo.toml` also adds
  `crossterm = "0.29"`, while ratatui 0.29 uses crossterm 0.28.1, so
  `Cargo.lock` builds both: input and raw mode go through 0.29, drawing
  through 0.28. Fix: drop the direct dependency and use the re-export
  (`ratatui::crossterm::...`); the notes list the new `[[package]]` names
  as the acceptance asks.
- **R42-4 (next): one item per commit.** F1-F5 are in `e07c74f`. The
  branch started before R41-3 was on master, so this round takes it;
  the fixes above go one per finding.
