**R37-9** (`37.md`, "After the merge"). When the old results were
archived on 2026-10-27, `bench.db` was gone and both services started
together. The GUI created the file; the engine's open failed:

```
[QUEUE-DB] open /home/ubuntu/subdollarbench/bench.db failed (database is locked: Error code 5: The database file is locked); falling back to temp-dir DB
```

- `/api/status` said `db_fallback: true`: the queue lived in
  `/tmp/sdb-queue-fallback-<pid>.db` and would not survive a restart
  (`src/web/server.rs:511-530`).
- Cause: `Store::open` switches to WAL (`src/report/store.rs:53`) before
  it sets `busy_timeout` (`:54`). The WAL switch on a new file needs an
  exclusive lock, and with no busy timeout yet the second opener gets
  `SQLITE_BUSY` at once instead of waiting.
- Restarting the engine alone fixed it (the file existed by then).

R36-4 (the stale `archive.rs` comment) was fixed in round 37 (`5ff1726`),
so it is not in this round.
