# Round 67: the bill matches the snapshot (one pinned provider per model); the GUI shows every run

Status: open
Opened: 2026-11-08, base `round-67-open` (operator: "yes, also fix gui")
Branch: `round67`
Rules: `2026-10-19.45` (unchanged. A pinned provider makes the bill match the price the cap already counts; it changes no grade and no cap. The operator confirms at the merge.)

## Why

- **R66-5: minimax was billed 1.75× its snapshot price** (reviewer,
  2026-11-08).
  - The grid key's usage went from $58.09 at the start of the minimax
    step to $70.96. That is $12.87 billed, against $7.34 at list price in
    `runs/.grid-v21-minimax-ledger.tsv`.
  - OpenRouter's own generation record agrees. `gen-1794092986-...`
    (2026-11-07 23:09 UTC, provider Nebius) cost $0.0005187, exactly
    input $0.15, output $0.60 and cache read $0.015 per M. A probe at
    07:47 UTC (provider ModelRun) was also 2× the snapshot's
    $0.075/$0.30/$0.0075.
  - **Cause:** the catalog's model-level price for
    `minimax/minimax-m3.1-flash` is one provider's off-peak rate (the
    MiniMax endpoint, with a time-of-day override). OpenRouter routes
    across 13 providers, and 11 of them charge $0.15/$0.60. The harness
    passes OpenRouter only a model id (`src/sandbox/omp.rs:644-653`), so
    routing picks the provider.
  - **It is general.** Provider prices vary for most models (the
    endpoints API, 2026-11-08):

    | model | providers | input $/M range |
    |---|---|---|
    | gpt-6-luna-pro | 6 | 0.05-0.20 |
    | mimo-v2.6-pro | 5 | 0.33-4.00 |
    | deepseek-v4.1-flash | 51 | 0.006-2.40 |
    | haiku-5.5 | 10 | 0.10-0.11 |

    The v2 grid happened to come out at +11% overall.
  - The $0.99 cap counts list price, so a model routed to a dearer
    provider gets more real budget than the cap says. The minimax
    careers had about $1.70 per phase. They are hidden
    (`.portal_hidden`), and the grid was stopped (operator, "yes").
- **R66-4: the GUI and the TUI miss runs.** `get_campaigns` sorts by the
  board order, then `out.truncate(50)` (`src/web/server.rs:1816`). There
  are 79 runs on disk, so low-scoring phases fall off.
- **R64-3: career numbering counts the rehearsal.** The portal named the
  minimax careers "career 2, 3, 4", because their $0 rehearsal took
  "career 1".
- **R66-3: no self-test for the probe race.** The fix landed (`eaddce4`,
  the reviewer) without a `grid.sh --self-test` case.

## Items

### F1. One pinned provider per model, priced from that provider

- Each row of `src/cost/model_prices.json` gains `provider`: the
  OpenRouter provider slug that serves that model for the bench. Its
  four prices are **that provider's** endpoint prices, from
  `/api/v1/models/<id>/endpoints`, not the model-level catalog price.
  - For each grid model (the five v2 and the four new ones), choose the
    provider whose endpoint price equals the current row. If none does,
    choose the cheapest with `status` 0 and uptime ≥ 99%, and update the
    row.
  - A changed price for a **v2** model is a Spec question first: its
    careers are published at the old price.
  - Avoid a provider whose endpoint has a time-of-day `overrides` block,
    unless it is the only one.
- **Every call goes to that provider only.** Find how omp passes
  OpenRouter provider preferences: its model config, request extras, or
  an OpenRouter preset. Send `provider: {order: [<slug>],
  allow_fallbacks: false}`, or its equivalent.
  - **If omp cannot send it, ask under Spec questions before building
    anything else.** Candidate alternatives: an OpenRouter preset named
    in the model id, or the account-level provider preferences.
  - A pinned provider that is down is a harness fault, handled as round
    65 F2 handles a 402: STOP, not a 0.
- `PRICE_OVERRIDES` (`src/cost/calculator.rs:452`) describes the
  **pinned provider's** pricing. Minimax's "2× the base rate 01:00-15:00
  UTC" goes, unless the pinned provider has it.
- A model without a `provider` refuses to launch a paid cell
  (`campaign::require_model_list_price`, as for a model without a row).
