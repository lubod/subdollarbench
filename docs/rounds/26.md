# Round 26: turns inside an attempt follow the dollar rule

Status: open
Opened: 2026-10-22, base: the commit tagged `round-26-open`
Branch: `round26`
Rules: `2026-10-19.39` -> `2026-10-19.40` (what the candidate experiences changes)

## Why

Round 23 D1 made dollars the session limit and set every stage's
`max_turns` to a 200-turn guard. But inside one attempt, the pipeline
still splits turns (R23-7, the `23.md` correction after deploy):

- the first session is capped at `INITIAL_TURN_CAP_WITH_FEEDBACK = 50`
  (`src/pipeline.rs` :394, `initial_turn_cap` :468);
- each feedback repair round is capped at `REPAIR_ROUND_TURN_CAP = 25`
  (:396).

So a cheap model still stops on turns, and its low price buys no extra
work, which is the problem round 23 set out to fix.

## Items

### R23-7. The initial / repair split is by dollars, not turns

- **Operator decision (2026-10-22): (b), drop the turn caps.**
  - The first session runs up to the attempt's dollar budget, with the
    200-turn guard as its only turn bound. The `INITIAL_TURN_CAP_WITH_FEEDBACK`
    and `REPAIR_ROUND_TURN_CAP` limits no longer apply to sdb-sql
    attempts.
  - A repair round runs only when the first session leaves money: the
    existing floor check (`repair_round_spend`, `src/scoring.rs` :111,
    and `BUDGET_FLOOR_USD`) decides.
    Its turn bound is whatever remains of the 200-turn guard.
  - The dollar split between the first session and the repair (option
    (a)) was rejected. A model that spends everything in its first session
    gets no repair; that's its choice of how to use its dollars.
  - Retired tasks keep the old caps only if a test needs them;
    otherwise remove the constants. Say which in the notes.
- Record the stop reason of each session (initial and repair), not only
  the last one.
- Since round 24, `src/scoring.rs` is fingerprinted but `src/pipeline.rs`
  isn't. Any turn rule that stays (the guard, how the guard is shared by
  the first session and the repair) lives in `src/scoring.rs`, so editing
  it moves the stamp.
- Call site: `initial_turn_cap(...)` at `src/pipeline.rs` ~:5104;
  `feedback_rounds` defaults to 1 (`src/scoring.rs` :14).
- Use the calibration cell's stop reasons as the evidence (how many
  initial sessions ended at 50 turns).
