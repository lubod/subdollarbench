## Why

The rules froze at `.41` (round 34, `docs/DECISIONS.md` #20). The
freeze listed some known gaps. This round takes the ones that affect
grading or the candidate's environment:

- **The sandbox image isn't stamped.**
  - `Dockerfile.sandbox` installs Rust `stable` and unpinned apt
    packages, so a rebuild can change the candidate's environment while
    the stamp stays the same.
  - The manifest records `omp_version` (`src/report/archive.rs:224`) but
    not the image.
  - The image is built by `update_sandbox_image`
    (`src/sandbox/omp_updater.rs:140`) when it's missing, or when
    `SUBDOLLAR_AUTO_UPDATE_OMP` opts in (`:195-240`).
- **Real cells assume the host user is UID 1000.**
  - `Dockerfile.sandbox` runs the candidate as `ubuntu`, which is UID
    1000.
  - Round 33 added `SANDBOX_UID`/`SANDBOX_GID` build arguments, but only
    CI passes them. `update_sandbox_image` doesn't.
- **The stage-4 dataset faults for about 1 seed in 5,000.**
  - `sentinel::build` (`src/verifier/sql/sentinel.rs:114`) fails when a
    seed's 40-step script leaves no writes or no ordered reads.
  - The persistence scenario reports that as a verifier fault
    (`src/verifier/sql/scenarios.rs:86`), and the run ends as
    `infra_error` (`src/verifier/sql/driver.rs:338`).
  - The upgrade sentinel (`src/pipeline.rs:4441`) calls the same
    `build`.
  - A scratch scan found 4 bad seeds in 20,000 (round 34, Implementer
    notes).

**After the freeze** (AGENTS.md, "Rules version"):

- This is its own round, with the operator's go-ahead at open.
- It bumps to `.42`, and careers restart at phase 1. No career on `.41`
  has been published.
- It needs the full gate. The 20-pass flake bar runs after round 37
  merges too, so one record covers both rounds, before the calibration
  career.
