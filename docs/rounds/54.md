### F3. "Seen failing" leaves a record

- `scripts/seen-failing.sh <test> <patch>`:
  - in a temporary worktree at HEAD, applies `<patch>` (the fix
    removed; the implementer writes it);
  - runs the one test under the cargo-test lock;
  - writes `<git-common-dir>/sdb-gates/seen-<HEAD>-<test>.txt` with the
    HEAD commit, the patch's sha256, the command, and the first failing
    assertion line;
  - copies the patch next to the record;
  - refuses (exit 1, no record) when the test passes with the patch;
  - `--replay <record>` reruns it.
- The template's Implementer notes cite the record path instead of
  quoting the line.

Acceptance:
- [ ] `scripts/seen-failing.sh --self-test`: a fixture crate whose test
  fails with the patch gives a record with the failing line; a patch
  that leaves the test passing gives no record and exit 1; `--replay`
