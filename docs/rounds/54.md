### F3. "Seen failing" leaves a record

- `scripts/seen-failing.sh <test> <patch>`:
  - in a temporary worktree at HEAD, applies `<patch>` (the fix
    removed; the implementer writes it);
  - runs the one test under the cargo-test lock;
  - writes `<git-common-dir>/sdb-gates/seen-<HEAD>-<test>.txt` with the
    HEAD commit, the patch's sha256, the command, and the first failing
    assertion line;
  - copies the patch next to the record;
  - refuses (exit 1, no record) when the test passes with the patch;
  - `--replay <record>` reruns it.
- The template's Implementer notes cite the record path instead of
  quoting the line.

Acceptance:
- [ ] `scripts/seen-failing.sh --self-test`: a fixture crate whose test
  fails with the patch gives a record with the failing line; a patch
  that leaves the test passing gives no record and exit 1; `--replay`
  reproduces the record — check: the output in the notes.

### F4. Git hooks for the commit format and the push scan

- Hooks live in `scripts/hooks/`; `scripts/install-hooks.sh` sets
  `core.hooksPath` for this clone (worktrees share it). Each hook can
  be bypassed with `--no-verify`, and AGENTS.md says when that is
  allowed (never for the push scan).
- **`commit-msg`:** on a `roundNN` branch the subject is
  `RNN <ID>: …` with one item ID, or `RNN: …` (status commits). A
  subject naming two IDs (`F1/F6`) is refused. Master's commits
  (`Merge roundNN: …`, `Round NN: …`) are not checked.
- **`pre-push`:** runs both secret-scan commands from AGENTS.md
  ("Commits", the reviewer's push checklist) over the range being
  pushed and refuses on any hit, printing the file name, never the
  value.

Acceptance:

    accepted;
  - a pushed range holding `OPENROUTER_API_KEY=x` refused, and a
    tracked `.env` refused, without printing the value;
  - a clean range accepted.
  — check: the output in the notes.

### F5. Citations are checked

- `scripts/check-cites.sh <round file>`: for each `` `path:N` `` or
  `` `path:N-M` `` in the file, the path exists at HEAD and N (and M)
  is within its length.
  - When the same backtick span or the next one names a symbol
    (`` `fn_name` ``), the cited line range or the five lines around it
    must contain that symbol.
  - It prints each failing cite.
- `gate.sh` runs it, as a warning only, on the round files the branch
  changes.

Acceptance:

  cite whose named symbol moved are both reported, and a good cite
  passes — test: `scripts/check-cites.sh --self-test`, seen failing
  (each case) by construction.
