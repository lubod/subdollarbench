## Items

### F1. An opencode phase records what OpenRouter billed

Round 83's `scripts/opencode-proxy.py` showed the way: a local proxy in
front of OpenRouter reads each response's `usage.cost` (OpenRouter's own
charge) and generation id. Put the same kind of proxy in the cell path:

- the runner starts one per run, on the run's sandbox network (or
  bound so only that run's container reaches it), and points
  `providers.openrouter.settings.baseURL` at it (the shape round 82
  proved); the proxy forwards to `https://openrouter.ai/api/v1` over
  TLS and changes nothing in the request or response;
- the egress allowlist still holds (the proxy is the only path out to
  the model API; nothing else opens);
- the runner sums the calls' `usage.cost` into `billed_usd` per attempt
  and resume, so the rollup's `billed_usd` (`src/campaign.rs`) is the
  phase's real bill; a call with no `usage.cost` is counted and logged,
  never silently priced;
- the proxy logs each call's generation id, model and cost to the run
  dir (`billed.jsonl`), without the key or the prompt.

## Review

### Interim review (before the gate; `Status: open`)

Read 2026-11-15 at `5c80af1`, on the operator's "have you reviewed
r85". **Two blockers in F1; F2 and F3 look right.** The `--ready` gate
hasn't run (it waits for a gap), so this is not the ready review.

- **R85-1 (blocker): the billing proxy is not reachable from a real
  cell, or if it is, the cell is no longer isolated.** The runner starts
  the proxy on the **host** (`BillingProxy::start`, which binds
  `0.0.0.0` and passes `--bind=0.0.0.0`) and points the agent at
  `host.docker.internal` with `--add-host=host.docker.internal:host-gateway`
  and `host.docker.internal` in `NO_PROXY`. But a cell's run network is
  created `--internal` (`src/sandbox/docker.rs:730`): it has no route
  out, the host gateway included. So either the agent can't reach the
  proxy and every call fails (a harness fault in every phase), or, where
  it can, the agent container reaches **every** host port bound on
  `0.0.0.0`, around the egress allowlist. The proof ran with host
  networking (`network == Some("host")` takes `127.0.0.1`, "as the tests
  do"), so the cell path was never exercised. Also, the proxy listens on
  `0.0.0.0` on the host, so anything on the LAN can relay through it
  for its lifetime.

  Wanted: the proxy lives **inside the run's network**, as the existing
  egress proxy does (a sidecar container, or the egress proxy itself
  serving the OpenRouter API path in HTTP and forwarding over TLS), and
  is reachable only from that network; nothing on the host listens on
  `0.0.0.0`; the agent keeps no route to the host. Prove it on the real
  cell path (an `--internal` run network, not host networking): the stub
  test through the same network setup a cell uses, and the real probe
  likewise.
- **R85-2 (blocker): a test that the cell is still isolated.** On the
  real cell network, the agent container can reach the billing proxy and
  OpenRouter through it, and **cannot** reach a host port (start a
  listener on the host's bridge address for the test) or any other
  destination. Seen failing with the old `--add-host` wiring.
- **R85-3 (accepted, noted): the real probe ran beside the deepseek
  grid** ($0.000804, disclosed in the notes). The grid's key-delta audit
  line was off by that much at most; no score is affected. Rerun the
  probe in a gap with the fixed design anyway (R85-1).
- **The F2 spec question:** yes, the line is `[KEY] initial account-key
  spend: $X USD`; read that. Haiku's $11.1591 matches the reviewer's
  reading.
- F2 and F3: read, not yet run by the reviewer; they are re-checked at
  the ready review.
