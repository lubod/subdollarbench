## Why

Operator, 2026-11-15 ("keep as it is and state real spending +
explanation"; DECISIONS #32). On `.47` haiku's 12 phases scored $4.58
at base rates while OpenRouter billed $11.16 for them (2.4x: Anthropic

but the opencode runner leaves it 0, so every `.47` career shows "—".

## Items

### F1. An opencode phase records what OpenRouter billed

Round 83's `scripts/opencode-proxy.py` showed the way: a local proxy in
front of OpenRouter reads each response's `usage.cost` (OpenRouter's own
charge) and generation id. Put the same kind of proxy in the cell path:

- the runner starts one per run, on the run's sandbox network (or
  bound so only that run's container reaches it), and points
  `providers.openrouter.settings.baseURL` at it (the shape round 82
  proved); the proxy forwards to `https://openrouter.ai/api/v1` over
  TLS and changes nothing in the request or response;
- the egress allowlist still holds (the proxy is the only path out to
  the model API; nothing else opens);
- the runner sums the calls' `usage.cost` into `billed_usd` per attempt
  and resume, so the rollup's `billed_usd` (`src/campaign.rs`) is the
  phase's real bill; a call with no `usage.cost` is counted and logged,
  never silently priced;
- the proxy logs each call's generation id, model and cost to the run
  dir (`billed.jsonl`), without the key or the prompt.

Acceptance:
- [ ] Through the round 79 stub (which returns a `usage.cost`), a
      two-turn session's `billed_usd` equals the stub's costs, and the
      `billed.jsonl` lines hold no key and no prompt text — test:
      `r85_f1_billed_from_the_calls`
- [ ] With the proxy gone mid-run, the run fails as a harness fault
      with a clear line, never a graded failure — same test or a sibling
- [ ] One real short session on a cheap model through the runner: the
      phase's `billed_usd` equals the sum of OpenRouter's per-call costs
      to the eighth decimal — check: notes (cap $0.05)
- [ ] Each test seen failing

### F2. Backfill the careers that ran before F1, per model

The careers that ran before F1 (haiku; deepseek and anything else
before the merge) have no per-call bill. Each campaign's `live.log`
records the key's spend at its start (`[SETUP] initial account-key
spend`). One model runs at a time (AGENTS.md) and the free track bills
$0, so a model's bill is the key's spend at its first campaign's start
subtracted from the next paid model's first one (or the key's spend
after its grid ended).

- A small, read-only tool computes each such model's bill from those
  lines and writes it as a **model-level** figure (not per career) into
  a file the board reads (`runs/` is data; say where), with its
  evidence (the two log lines and their campaign ids).
- The board shows a model-level bill as such ("billed, whole model,
  measured from the key"), never split across careers.

Acceptance:
- [ ] On fixture logs for two models in turn, the tool gives each
      model's bill from the two key readings, and refuses when two paid
      models' campaigns overlap in time — test: `r85_f2_backfill_from_key_readings`
- [ ] For haiku on `.47`, the tool gives $11.16 (91.0495 to 102.2086)
      — check: notes

### F3. The page explains it

On the board and the results page, next to the scored / billed column,
one short explanation, in the page's plain style:

- scores and the $0.99 per phase limit use each model's **base** price
  list; the billed column is what OpenRouter actually charged;
- the gap is the providers' surcharges (named per model from
  `PRICE_OVERRIDES`, `src/cost/calculator.rs`: haiku 5x above 100k
  prompt tokens; luna and luna-pro 2x above 272k; deepseek 2x in
  weekday peak hours, and it runs off-peak; minimax 2x 01:00-15:00 UTC,
  and it runs off-peak);
- the ratio billed / scored per model, so a reader sees it at a glance.

Acceptance:
- [ ] The rendered board for a fixture with one model at 2.4x shows the
      scored cost, the billed cost, the ratio and the explanation naming
      that model's surcharge — test: `r85_f3_board_explains_the_bill`
- [ ] A model with no billed figure still shows "—" and no ratio —
      same test
