### G2. A ticket has one deadline, not one per session

`ticket_timeout_min*60` is handed to the first session and again to the
repair session; with one feedback round it's about 2× the ticket's
time-out. Pass an absolute deadline so a ticket's sessions together
never exceed it; a lite attempt (and a full attempt) doesn't start when
the wall has passed or only a minute is left.

Acceptance:
- [x] A ticket whose first session ended at its deadline gets no second
      session of the same budget — test: `r93_g2_one_deadline_per_ticket`
- [x] A lite attempt after the wall doesn't run — test:
      `r93_g2_no_lite_after_the_wall`

### G3. Spend survives a crash, and zero doesn't mean unlimited

- A pipeline error or a kill after the agent has spent writes a faulted
  rollup with the spend so far (and the cell doesn't look stalled).
- `--budget-usd 0` (or negative) is refused except for a rehearsal
  (`--rehearsal` is explicitly $0); today 0 means no limit.
- `validate_chain` refuses a predecessor with a different `budget_usd`
  or `wall_min` (or marks the career tainted).

Acceptance:
- [x] A killed cell's rollup keeps the spend — test:
      `r93_g3_spend_survives_exit`
- [x] `--budget-usd 0` refuses a non-rehearsal launch — test:
      `r93_g3_zero_budget_refused`
- [x] Chain with a different budget refuses — test:
      `r93_g3_chain_validates_budget_and_wall`

### G4. The sidecar and the session log can't lose a run silently

- The proxy's accept loop catches per-connection and thread-start
  errors; client reads have a timeout.
- The audit/reconcile `[COST]` and `[BILLED]` lines are emitted after
  READY or a limit too (the pump currently stops).
- A spawned resume attempt's failure doesn't drop the earlier attempts'
  stats.

Acceptance:
- [x] A thread-start failure doesn't kill the sidecar — test:
      `r93_g4_sidecar_thread_failure_survives`
- [x] The `[BILLED]` line appears after READY too — test:
      `r93_g4_audit_lines_after_ready`

### G5. One grid's state is its own

- Canaries, audits and stops keep the grid's ledger name in their file
  names, so two grids (or a rehearsal and a paid grid) can't clobber
  each other's markers.
- A grid holds a per-ledger lock file while running.
- The TERM trap kills the lanes it started; a stop file isn't deleted
  silently on a restart; a balance hold rechecks the balance on release.

Acceptance:
- [x] Two grids on different ledgers don't affect each other's lanes —
      test: `r93_g5_grid_state_is_per_ledger`
- [x] A restart never deletes the stop reason
