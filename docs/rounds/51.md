## Items

### F1. `publish.sh` pushes only to a marked target (R44-9)

- Before `rsync --delete`, the target must hold a marker file
  `.sdb-publish` (checked with `rsync --list-only` or `ssh test -f`).
  Without it, `publish.sh --yes` refuses and prints how to create it.
- The dry run (no `--yes`) prints the `*deleting` lines, and refuses
  when they include anything outside the export's own file set.
- The export writes `.sdb-publish` itself, so `--delete` never removes
  the marker.

Acceptance:
- [ ] `publish.sh --self-test` (a local target directory): no marker →
  refused, nothing deleted; marker → pushed; a stray file in the target
  is listed by the dry run — check: the output in the notes, seen
  failing on master.

### F2. One secret list (R44-10, first part)

- `publish.sh` runs the binary's scan (`subdollarbench portal
  --secret-scan <dir>`, new, exit 1 with the matching file and line)
  instead of its own `grep`. `secret_patterns` stays the one list.
- The scan never prints the matched value: file, line and pattern name
  only.

Acceptance:
- [ ] A fixture export with an `OPENROUTER_API_KEY=` line, a
  lower-case `bearer` token and an `sk-or-v1-` string is refused for
  each; a clean one passes; the output holds none of the values — test:
  `r51_f2_secret_scan_cli`, and `publish.sh --self-test`.

### F3. Unknown effort shows nothing (R44-10, second part)

- `career_from_leaf` (`src/report/grid.rs:443`) keeps an unknown effort
  empty; the board, the results page and the Run view show nothing
  there (§4.1).
- Grouping by model still separates an unknown effort from `high`.

Acceptance:
- [ ] A fixture rollup with no `effort` renders no "high" and groups
  apart from a `high` career — test: `r51_f3_unknown_effort_blank`,
  seen failing on master.

### F4. The grid dates span the careers, in minutes (R44-14)

- "Grid dates" runs from the earliest phase-cell start of any ranked
  career to the latest finish, printed `YYYY-MM-DD HH:MM UTC`.

Acceptance:
- [ ] A fixture with two careers, each of four phases, prints the first
  phase's start and the last finish, without seconds — test:
  `r51_f4_grid_dates`.

### F5. The page says how cost is priced (Q8 a)

- The results page's "What it measured" table gains a "Prices" row: the
  snapshot date (`as_of` in `src/cost/model_prices.json`), "base rates
  per call", and each ranked model's overrides that the snapshot doesn't
  price. The overrides live in one table next to the snapshot reader
  (not in `model_prices.json`, which is graded), and a test checks that
  every ranked grid model has an entry (an empty one is allowed).
- The overrides as of 2026-10-28 (`46.md`, "Out of scope"; Q8):
  Haiku 5.5, 5x the prompt rate above 100k prompt tokens; gpt-6-luna,
  2x above 272k; deepseek-v4.1-flash-1017, 2x in weekday peak hours;
  mimo-v2.6-flash and qwen3.8-flash, none.

Acceptance:
- [ ] The results page shows the Prices row with the snapshot date and
  the three overrides — test: `r51_f5_prices_row`.
- [ ] Each of the five grid models has an overrides entry — test:
  `r51_f5_every_grid_model_has_an_entry`.
