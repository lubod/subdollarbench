## Items

### F1. `publish.sh` pushes only to a marked target (R44-9)

- Before `rsync --delete`, the target must hold a marker file
  `.sdb-publish` (checked with `rsync --list-only` or `ssh test -f`).
  Without it, `publish.sh --yes` refuses and prints how to create it.
- The dry run (no `--yes`) prints the `*deleting` lines, and refuses
  when they include anything outside the export's own file set.
- The export writes `.sdb-publish` itself, so `--delete` never removes
  the marker.

Acceptance:
- [ ] `publish.sh --self-test` (a local target directory): no marker →
  refused, nothing deleted; marker → pushed; a stray file in the target
  is listed by the dry run — check: the output in the notes, seen
  failing on master.

### F2. One secret list (R44-10, first part)

- `publish.sh` runs the binary's scan (`subdollarbench portal
  --secret-scan <dir>`, new, exit 1 with the matching file and line)
  instead of its own `grep`. `secret_patterns` stays the one list.
- The scan never prints the matched value: file, line and pattern name
  only.

Acceptance:
- [ ] A fixture export with an `OPENROUTER_API_KEY=` line, a
  lower-case `bearer` token and an `sk-or-v1-` string is refused for
  each; a clean one passes; the output holds none of the values — test:
  `r51_f2_secret_scan_cli`, and `publish.sh --self-test`.

### F7. The image-lookup test doesn't share state with other tests (R43-2)

- `r43_f3_board_no_inspect_per_request` counts through the process-wide
  `SANDBOX_IMAGE_INSPECTS` and `SANDBOX_IMAGE_CACHE`
  (`src/campaign.rs:1962-1980`). A parallel lib test that serves a live
  cell with no image (`src/web/server.rs:5054`) fills the same cache,
  so its "one inspect" and "zero inspects" asserts can be off by one.
- Inject the lookup: `live_cell_image` takes the fallback (a cache
  value or a closure), and the test passes its own counter and cache.
  Production keeps one process-wide cache, refreshed at most once a
  minute.
- Don't hold the cache mutex across the `docker` subprocess: take the
  lock, check the age, release it, inspect, then store.

Acceptance:
- [ ] `r43_f3_board_no_inspect_per_request` uses no process-wide state
  — check: the reviewer reads it.
- [ ] Two threads that call the production fallback on an empty cache
  don't block each other for the subprocess's duration, and the cache
  holds a value afterwards — test: `r51_f7_cache_lock_not_held_across_inspect`
  (with an injected slow lookup).
