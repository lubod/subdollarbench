### F1. The perf score breaks points ties

  `perf.score` (`CareerRollup.perf`), or the phase's own for a cell with
  no career.

  first; a score sorts above none), then points per dollar, then cost.
- The model groups (`model_groups`, `src/report/grid.rs:542`) use the
  same order, so the median career and the rank groups (`2=`) follow it.
- Equal points compare perf exactly (no epsilon on points; perf compares
  as recorded).

### F3. The variance line and the even median (R44-6, R44-8)

- **R44-6:** `variance_report` prints `ranked (A worst 12.0 < B best
  15.0)` (`src/report/grid.rs:1273`). When the pair is ranked, A's worst
  is better than B's best, so the `<` reads backwards. Print it the way
  the ranking reads (for example `A worst 15.0 ≥ B best 12.0`).
- **R44-8:** with an even number of careers, `(n−1)/2` of the
  best-first list (`src/report/grid.rs:575`) picks the better middle.
  Use the worse one (`n/2`), which is conservative. With 3 careers per
  model (the grid) nothing changes.

Acceptance:
- [x] The ranked variance line reads in the ranking's direction — test:
  `r47_f3_variance_line_direction`.
- [x] With 2 careers the model's median is the worse one; with 3 it is
  the middle — test: `r47_f3_even_median_is_the_worse`.

### F4. A superseded branch doesn't count (R44-7)

- Two leaves from one predecessor both become careers today and share
  its phases. A refork (`ReforkInfo { of, reason }`,
  `src/campaign.rs:2361`) names the successor it supersedes.
- The board drops the branch that a refork superseded (the cell named
  by `refork.of` and every later phase chained from it), as it drops
  hidden and poisoned lineages (`drop_lineage`,
  `src/report/grid.rs:123`). The superseded branch stays visible in the
  Run view, marked superseded.

Acceptance:
- [x] A fixture with a predecessor, its first successor chain, and a
  refork successor gives one career (the refork's) — test:
  `r47_f4_refork_supersedes`, seen failing on master.

### F5. Every ranked career carries one fingerprint (R44-13)

- A ranked career with no recorded fingerprint adds nothing to
  `ranked_fingerprints` (`src/report/grid.rs:1213-1218`), so it passes
  silently when the other careers share one.
- A ranked career must carry exactly one fingerprint. One with none, or
  with more than one, makes the export refuse (as a mixed set does),
  naming the career.

Acceptance:
- [x] A fixture with one fingerprint-less ranked career next to two
  stamped ones refuses the export and names it — test:
  `r47_f5_career_without_fingerprint_refused`, seen failing on master.
