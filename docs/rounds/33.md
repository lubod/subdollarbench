## Why

The third GitHub CI run (`40171750050`; `29.md`, "R29-1") built the
image, and then 30 tests failed. The cause:

- The candidate container's stderr reads "chmod: changing permissions of
  'start.sh': Operation not permitted". So the server never starts, and
  stage 0 fails as "server unreachable".
- `Dockerfile.sandbox` runs as `ubuntu`, which is UID 1000. On the bench
  host the workspace's owner is UID 1000 too. On the GitHub runner it is
  the runner's user, usually 1001.

**The flake bar is running** (until about 23:30 UTC on 2026-10-25).

- Nothing here is graded: `Dockerfile.sandbox` and `ci.yml` are in
  neither list.
- The bench's own image is not rebuilt, and the build argument's default
  keeps it unchanged.
- **Don't run `cargo test`, the gate or local Docker builds while the bar
  runs** (check first with `ps -eo cmd | grep '[f]lake-bar'`).

## Items

### F1. A build argument for the sandbox user's UID

- In `Dockerfile.sandbox`, add `ARG SANDBOX_UID=1000`.
- When it differs from 1000, give `ubuntu` that UID (for example
  `usermod -u "$SANDBOX_UID" ubuntu`), and fix the ownership of
  `/home/ubuntu` and `/workspace`.
- With the default, the image is the same as today.
- In `ci.yml`, build with `--build-arg SANDBOX_UID=$(id -u)`.
- If the runner's GID also matters, handle it the same way, and say so in
  the notes.
