## Why

The TUI captured at 110 columns during the 2-lane smoke (2026-10-31,
operator "put it"):

```
subdollarbench tui · cells ● 2 running · rules 2026-10-19.44 · image — · queue 0 ?help q quit
│1   deepseek-v4.1-flash-1017      ▶····················     0.0/10    $0.0000   —       run t0 32/200       │
│3   deepseek-v4.1-flash-1017      ■■■■■■■··············     10.0/76   $0.2769   36.1    done · ladder end   │
│4   deepseek-v4.1-flash-1017      ■■■■■················     6.0/10    $0.1654   36.3    cancelled           │
│ticket $ 0.0342   campaign $ 0.0000 / 0.50   wall 5/480 m                                                   │
```

- **The points scale changes with the state.** All three rows are
  phase-1 cells. The finished one shows `/76`; the running and cancelled
  ones show `/10`. `max_points` (`src/tui.rs:326`) returns 76 whenever
  the rollup has a `career` block, and the rollup's `max_points`
  otherwise.
- **Campaign spend reads $0 while ticket 0 runs.** The live line prints
  `live.campaign_spent` (`src/tui.rs:514-519`), which counts only
  finished tickets, so it is lower than the ticket line above it.
- **`image —` always.** The header reads `/api/status`'s
  `sandbox_image` (`src/tui.rs:392`), and `StatusResponse` has never
  had that field. This is the R42-7 pattern: a field name the API
  doesn't serve.
- **R52-1** (`52.md`, Review): with the engine unreachable,
  `status_field` (`src/tui.rs:375-377`) prints the whole error text, so
  at 80 columns the `?help q quit` hint is cut again (R42-6).

## Items

### F1. One points scale per row

- A row's points and denominator say the same thing for every state:
  - a career phase (the rollup has `phase`) shows its career's points
    over 76;
  - a cell outside a career shows its own points over its `max_points`.
- A running career phase counts the career's points so far (the chain's
  points plus this phase's).

Acceptance:
- [ ] The four rows of `docs/rounds/55-fixtures/api-campaigns.json`
  (two running phase-1 cells, one done with a `career` block, one
  cancelled; all `phase: 1`, `max_points: 10`) use one denominator —
  test: `r55_f1_points_scale_per_row`, seen failing on master.

### F2. The campaign spend includes the running ticket

- The live line's campaign spend is the finished tickets' spend plus
  `live.ticket_spent`, so it is never below the ticket line.
- Name each field in the notes with the API response it comes from.

Acceptance:
- [ ] The `_w0` running row of `docs/rounds/55-fixtures/api-campaigns.json`
  (`campaign_spent` 0.0, `ticket_spent` 0.034466) reads
  `campaign $ 0.0345`; the `_w1` row (0.039371814 after ticket 0, plus
  its ticket's 0.004622) reads `campaign $ 0.0440` — test:
  `r55_f2_campaign_spend_counts_ticket`, seen failing on master.

### F3. The header's image is a field the API serves

- `/api/status` serves `sandbox_image` from the cached lookup
  (`cached_sandbox_image_id`, `src/campaign.rs`, round 51 F7: no
  `docker` call per request).
- The header shows its short id; when the lookup fails, it shows the
  image field not at all, rather than `—`.

Acceptance:
- [ ] `/api/status` has `sandbox_image`, and a header built from that
  response shows the short id — test: `r55_f3_header_image_from_status`
  (start from `docs/rounds/55-fixtures/api-status.json`, captured
  without the field; the new field added to it), seen failing on
  master.

### F4. An unreachable engine keeps the hint (R52-1)

- The header's status field is cut to fit, for example
  `engine ● unreachable (connection refused…)`, before the hint ever
  is. The full error goes to the live pane or the help.

Acceptance:
- [ ] With the error text from a refused connection
  (`error sending request for url (http://127.0.0.1:3000/api/status)`),
  the header at 80 columns ends with `?help q quit` — test:
  `r55_f4_unreachable_header_fits_80`, seen failing on master.
