## Why

The TUI captured at 110 columns during the 2-lane smoke (2026-10-31,
operator "put it"):

```
subdollarbench tui · cells ● 2 running · rules 2026-10-19.44 · image — · queue 0 ?help q quit
│1   deepseek-v4.1-flash-1017      ▶····················     0.0/10    $0.0000   —       run t0 32/200       │
│3   deepseek-v4.1-flash-1017      ■■■■■■■··············     10.0/76   $0.2769   36.1    done · ladder end   │
│4   deepseek-v4.1-flash-1017      ■■■■■················     6.0/10    $0.1654   36.3    cancelled           │
│ticket $ 0.0342   campaign $ 0.0000 / 0.50   wall 5/480 m                                                   │
```

- **The points scale changes with the state.** All three rows are
  phase-1 cells. The finished one shows `/76`; the running and cancelled
  ones show `/10`. `max_points` (`src/tui.rs:326`) returns 76 whenever
  the rollup has a `career` block, and the rollup's `max_points`
  otherwise.
- **Campaign spend reads $0 while ticket 0 runs.** The live line prints
  `live.campaign_spent` (`src/tui.rs:514-519`), which counts only
  finished tickets, so it is lower than the ticket line above it.
- **`image —` always.** The header reads `/api/status`'s
  `sandbox_image` (`src/tui.rs:392`), and `StatusResponse` has never
  had that field. This is the R42-7 pattern: a field name the API
  doesn't serve.
- **R54-3** (`54.md`, "After the merge"; operator "55"): the pre-push
  hook refused its own source. F5 is off the round's theme, but it is
  small and ungraded, and round 56 is full.
- **R52-1** (`52.md`, Review): with the engine unreachable,
  `status_field` (`src/tui.rs:375-377`) prints the whole error text, so
  at 80 columns the `?help q quit` hint is cut again (R42-6).

Findings:

- **R55-1 (blocker): the campaign spend counts the finished ticket
  twice.**
  - F2 adds `live.ticket_spent` whenever `state` is running
    (`src/tui.rs:577`).
  - When a ticket's verdict lands, `on_stage` writes the rollup
    (`src/main_campaign.rs:745`), and `campaign_spent` then includes
    that ticket (`:177`). `ticket_spent` keeps the same ticket's spend
    until the next ticket starts (`:275`), and `state` stays `running`.
  - So the line overcounts:
    - between tickets;
    - through the whole end-of-phase perf run (`:851`).
  - Example, lane 1's final live block (ticket 6, `phase: crash`,
    `ticket_spent` 0.059693, `campaign_spent` 0.253354): had the state
    still been `running`, the line would read `campaign $ 0.3130`
    against $0.2534.
  - Fix: add `ticket_spent` only while `live.ticket` has no record in
    `rollup.stages` (each record's `id` is its ticket).
  - Acceptance: the `_w0` and `_w1` rows still read `0.0345` and
    `0.0440`. A running row whose `rollup.stages` holds `live.ticket`
    reads `campaign_spent` alone. Seen failing on `839d8dc`.
- **R55-2 (blocker): a real value on a line starting with `++` passes
  the hook.**
  - The real-value loop skips every diff line starting with `+++` as a
    file header (`scripts/hooks/pre-push:114`). An added line whose
    text starts with `++` is also a diff line starting with `+++`.
  - The reviewer's probe, in a temp repo with a fake `.env` value:
    - `x = "<value>"` is refused (exit 1);
    - `++<value>` is accepted (exit 0).
  - F5 says a real value is refused on every line.
  - Fix: skip only real file headers, `+++ b/…` and `+++ /dev/null`, as
    the line after a `--- ` header.
  - Acceptance: `hooks/self-test.sh` refuses a `++<value>` line, seen
    failing on `839d8dc`.
- **R55-3 (next → round 57): the allowlist is read from the working
  tree** (`scripts/hooks/pre-push:14`), not from the commit being
  pushed. A push from a checkout with an uncommitted edit to the list
  uses the edit. Read it with `git show <local_sha>:scripts/secret-scan-fixtures.txt`.
