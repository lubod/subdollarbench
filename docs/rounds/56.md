## Why

The 2-lane smoke after the round 53 deploy (2026-10-31; lanes `…_084959_w0`
and `…_085009_w1`, DeepSeek v4.1 Flash, phase 1):

- **Lane 1 lost 2 hours on ticket 2.** At 09:02:47 the model ran
  `./start.sh --port 5580 --data /tmp/sdbdata` in the foreground with
  `"timeout": 0` (`56-fixtures/hung-tool-session-tail.jsonl`). `start.sh`
  `exec`s the server, so the call never returned. There was no open
  connection to the provider and nothing was spent. The only thing
  that ended it was omp's `--max-time=7200s` (`src/sandbox/omp.rs:111`) at
  11:01:32. Ticket 2 then passed on the code written in its first 70
  seconds. The ticket cost $0.0125 at list price, but 2 hours of wall
  time and $0.2255 of compute floor (`effective_cost_usd` 0.2381,
  `src/cost/calculator.rs:149`).
- **The default cap is 300 s; `timeout: 0` turns it off.** Lane 0 made
  the same foreground server start with `"timeout": null` and got
  `[Command timed out after 300 seconds]`, then carried on
  (`56-fixtures/capped-tool-session-excerpt.jsonl`). Across the 307
  sdb-sql sessions on this host (9,057 tool calls), no call that
  returned ran longer than 300.1 s. Five sessions hit the 300 s cap,
  all with a foreground server start.
- **The live line said "Model is reasoning" for 2 hours.** The heartbeat
  (`src/sandbox/omp.rs:1166-1180`) prints that text after any 3 s of
  silence, even while a tool call is in flight.
- **The audit key delta has no meaning with two lanes.** Ticket 2's
  `live_spend_delta_usd` is $0.2143 against $0.0125 at list price. That
  figure is the drop in the shared key's balance over 2 hours, while
  lane 0 ran its tickets 2-6 (`src/pipeline.rs:3530-3537`). The cap and
  the score are unaffected, because they use list price
  (`resolve_api_cost`, `src/cost/calculator.rs:140`). What is lost is
  the check of the provider bill against metered cost (the earlier
  smoke: key delta $0.3323 against $0.2769 metered).
- **`concurrent_cells` reads 1 on both lanes.** It comes only from
  `SDB_CONCURRENT_CELLS` (`src/main_campaign.rs:863`), which `grid.sh`
  sets and a hand-started lane doesn't.

## Operator decision (before open)

F1 ends a session early. **Recommendation: no rules bump.** The guard
fires only on a tool call that has run 10 minutes or longer, which no
returned call has done (the longest was 300.1 s in 9,057). A call like
that never gave control back to the model before `--max-time` anyway.
So the verdict is the one `--max-time` would give, just sooner, and the
candidate sees nothing new. The alternatives were rejected because the
candidate sees them, so each needs a bump: the policy blocking
`timeout: 0`, or killing the hung process so the model goes on.

It's still a graded-path change (`src/sandbox`, `src/pipeline.rs`), so
the round needs the full gate, and the 20-pass flake bar runs on its
content (DECISIONS #22, #23: after all rounds merge, in any case).

## Items

### F1. A tool call that hangs ends the session

- The session tail (`src/sandbox/omp.rs`, the reader loop around
  `:1121-1183`) tracks the tool call in flight: a `tool_execution_start`
  with no `toolResult` after it.
- When one call has been in flight for `SDB_TOOL_STALL_S` seconds
  (default 600; tests set it low), the harness ends the session as
  `--max-time` does:
  - the live line says, for example,
    `[STALL] bash ran 600 s without returning (./start.sh --port 5580 …); ending the session, graded on the workspace as is`;
  - the ticket's manifest records
    `stall: {tool, command, started_at, ended_at}`;
  - grading runs as it does after `--max-time`.
- Nothing the candidate sees changes: no new prompt text, no policy
  block.

Acceptance:
- [ ] Replaying `56-fixtures/hung-tool-session-tail.jsonl` with
  `SDB_TOOL_STALL_S=2` ends the session within 5 s, and the manifest
  has `stall.command` starting with `cd /workspace && rm -rf /tmp/sdbdata`
  — test: `r56_f1_hung_tool_ends_session`, seen failing on master.
- [ ] Replaying `56-fixtures/capped-tool-session-excerpt.jsonl` (start,
  then a `toolResult` after the call ran) records no `stall` — test:
  `r56_f1_returned_tool_is_not_a_stall`.

### F5. The heartbeat is not activity (the Board's hung-agent warning)

- The Board warns `no activity for …` when a running cell's
  `live.last_activity_at` is over 120 s old, and turns red at 300 s
  (`src/web/index.html:1997-1999`). During lane 1's 2-hour hang it stayed
  green. `apply_live_line` (`src/main_campaign.rs:215`) refreshes
  `last_activity_at` on every log line, so the `[WAITING]` heartbeat,
  printed every 3 s, kept it fresh (`status.json` at 10:37:30 had
  `last_activity_at` 10:37:26, 95 minutes into the hang).
- A `[WAITING]` heartbeat line no longer moves `last_activity_at`.
  Every other line still does.

Acceptance:
- [ ] Applying a `[WAITING] … (elapsed: 5682s)` line keeps
  `last_activity_at`; applying a `[TELEMETRY]` line moves it — test:
  `r56_f5_heartbeat_is_not_activity`, seen failing on master.

### F6. Docker-running tools refuse while a cell runs (R54-2)

- During the 2-lane smoke, round 54's real grid self-test and live proof
  ran 09:07-09:31 next to two paid cells (`54.md`, R54-2). AGENTS.md
  ("While a cell runs") allows only unit tests and `gate.sh --fast`,
  but nothing checks it.
- Each of these refuses to start while a live campaign lock is held in
  the cells' runs dir (`live_lock_holders_in`, `src/campaign.rs:1627`),
  naming the lock's campaign. That dir is `$ROOT/runs`, or
  `SDB_CELL_RUNS_DIR` for the self-test. A tool's own temp
  `SDB_RUNS_DIR` is not checked:
  - `scripts/seen-failing.sh`, when the test is a live proof
    (`scripts/live-proofs.sh` lists it);
  - `grid.sh --self-test --real`;
  - `scripts/flake-bar.sh`;
  - `scripts/gate.sh` in full mode.
- `SDB_ALLOW_BESIDE_CELL=1` overrides it, for the operator only. The
  override is recorded in the gate or seen-failing record.

Acceptance:
- [ ] With `SDB_CELL_RUNS_DIR` at a temp dir where a lock is held on
  worker 0 (the hidden lock-hold command), each of the four refuses and
  names the campaign. With no lock, each starts — test:
  `scripts/beside-cell-self-test.sh`, seen failing on master.
